# 初期スキーマの統合と D1 の再作成

## 方針

未リリースのため、従来の 6 本を `migrations/0001_initial.sql` に統合する。
予約投稿・認証情報・OAuth の状態・回答済みの集合・匿名回答の 5 表と索引を初めから作成する。
旧データを移す DELETE・UPDATE・ALTER・DROP は含めない。

利用者の指示により、本番用 `skyshare` と開発用 `skyshare-develop` を削除し、同名で作り直す。
既存データとマイグレーション履歴は引き継がない。別用途の DB と R2、Worker のコード・シークレットは変更しない。

## 手順

1. 従来の全マイグレーションを適用した SQLite と統合版のテーブル・列・主キー・索引が同一であることを確認する。
2. 対象アカウントと DB の ID、配備済み Worker とプレビューの接続先を確認する。
3. 本番用・開発用 DB を削除し、同名で作成する。
4. 両 DB に `0001_initial.sql` のみを適用し、5 表・索引と未適用 0 件を確認する。
5. Worker と各プレビューの D1 バインディングを、新しい DB の ID へ変更する。
6. 再採用ブランチにも統合版を反映し、両プレビューの再配備と HTTP 応答を確認する。

## 互換性

統合版を既存 DB に追加適用することはできない。ローカルの旧 D1 も不要なら作り直してから適用する。
過去のマイグレーションと手順は Git 履歴に保存されている。
2026-10-30 に行った `0006_survey.sql` だけの追加適用は、この DB 再作成で置き換える。

## 検証結果

- ローカル SQLite で、従来の 6 本を適用した場合と列・主キー・索引・外部キーの定義が一致した。
- 本番用・開発用 D1 を削除し、同名で作り直した。
- 両 DB の履歴は `0001_initial.sql` だけで、未適用は 0 件、アプリ用の 5 表が存在する。
- 開発用 Worker と既存の 10 プレビューを新しい開発用 DB に接続し直した。他のバインディングは維持した。
- 本番 Worker は現時点で D1 バインディングを持たないため、コードや接続設定は変更していない。
- 再採用ブランチでマイグレーション・予約・アンケート関連のテスト 480 件、型検査と仕様検査が通過した。
