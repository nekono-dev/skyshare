# Requirements Document

## Project Description (Input)

運営者は、ログインした利用者の動向を把握するため、期間を限った匿名のアンケートの回答を集めたい。しかし、回答を保存する仕組みがなく、回答者を特定できない形で保存することも、同じ利用者（複数のアカウントを含む）に何度も聞かないようにすることも、期間を過ぎた回答を確実に消すこともできない。現状、サーバー側のデータの保管先には予約投稿のものしかない。

回答済みの利用者の集合と匿名の回答を、互いに結びつけない 2 種類のデータとして保存し、重複を防ぎ、保持期限を過ぎたデータを既存の毎分の定期実行の日次の 1 枠で自動的に削除する（`docs/features/survey-api/brief.md`、`docs/architecture.md` に従う）。

## Introduction

ログインした利用者のアンケートへの回答を、回答者を特定できない形で受け付けて保存する。回答済みかどうかの確認、回答済みとしての登録、回答の保存を API として提供し、同じ利用者による重複を防ぐ。保持期限を過ぎたデータは定期実行で削除する。アンケートの内容と期間の判定は、承認済みの survey-definition の設定に従う。

## Boundary Context

- **In scope**:
  - 回答済みの確認、回答済みとしての登録、回答の保存の 3 つの操作。
  - 回答の検証（設定との照合、「回答しない」を含む回答の拒否）と、期間外・未定義のアンケートの拒否。
  - 回答者を特定できない形での保存と、同じ利用者による重複の防止。
  - 保持期限を過ぎたデータの定期的な削除。
  - 回答を保存するための秘密の鍵の用意（全環境）。
- **Out of scope**:
  - 設定の形式・検証・期間と保持期限の判定（survey-definition）。
  - 質問の描画、回答済みの端末側の記録、確認や登録を呼び出す判断（survey-form・choice-question）。
  - 運営者の手順と、変数からの期限切れのアンケートの除去（survey-operation）。
  - 回答の集計・閲覧・取り消し・訂正。
  - プライバシーポリシーの更新。
- **Adjacent expectations**:
  - アンケートの内容・期間・保持期限は、survey-definition の検証済みの設定から得る。設定が得られないときは、アンケートが存在しないものとして扱う。
  - 画面側（survey-form）は、「回答しない」を含む回答を送らない。この API も独立して拒否する。
  - 運営者は、過去のアンケートの設定を、データの削除が終わるまで設定の元に残す。設定から消えたアンケートのデータは、この機能では削除できない。
  - 回答の取り消しはできないため、利用者に見せる説明は別の機能が担う。

## Requirements

### Requirement 1: ログインと応答の共通の規則

**Objective:** As a 利用者, I want 自分のアカウントの回答状況だけが、自分のログインを通じて扱われてほしい, so that 他人の名義での回答や、回答状況の流出が起きない

#### Acceptance Criteria

1. If ログインしていない利用者がいずれかの操作を求めたとき、then the アンケート API shall 未認証として拒否し、データの保管先に触れない
2. The アンケート API shall 回答者の識別子を、利用者の入力ではなくサーバー側のログインの状態からだけ得る
3. The アンケート API shall すべての応答を、中継点や端末に保存させない指定で返す
4. If 入力の形式が不正なとき、then the アンケート API shall 不正な要求として拒否し、データの保管先に触れない
5. If 予期しない失敗が起きたとき、then the アンケート API shall 内部の情報を含まない失敗として応答する

### Requirement 2: 対象のアンケートの判定

**Objective:** As a 運営者, I want 開催中のアンケートにだけ操作できるようにしたい, so that 期間外や存在しないアンケートに回答や記録が残らない

#### Acceptance Criteria

1. If 指定されたアンケートが設定に存在しないとき、then the アンケート API shall 見つからないものとして拒否する
2. If 指定されたアンケートが開催期間外のとき、then the アンケート API shall 見つからないものとして拒否し、データの保管先に触れない
3. If アンケートの設定を取得できないか、設定が無いとき、then the アンケート API shall アンケートが存在しないものとして扱う
4. While アンケートが開催期間内のとき、the アンケート API shall 回答済みの確認・回答済みとしての登録・回答の保存を受け付ける
5. If 回答を匿名にするための秘密の鍵が設定されていないとき、then the アンケート API shall 利用できない状態として応答し、何も保存しない

### Requirement 3: 回答済みの確認

**Objective:** As a 利用者, I want 自分のアカウントが回答済みかを確認したい, so that 同じアンケートに何度も答えずに済む

#### Acceptance Criteria

1. When 開催中のアンケートについて回答済みの確認が求められたとき、the アンケート API shall 現在のアカウントが回答済みかどうかを真偽で返す
2. When 現在のアカウントが回答済みとして登録されているとき、the アンケート API shall 回答済みとして返す
3. When 現在のアカウントが回答済みとして登録されていないとき、the アンケート API shall 未回答として返す
4. The アンケート API shall 回答済みの確認で、回答の内容も回答した時刻も返さない
5. The アンケート API shall 回答済みの確認をデータの保管先への読み取り 1 回で行う

### Requirement 4: 回答済みとしての登録

**Objective:** As a 利用者, I want 別の端末などで回答済みの自分のアカウントを、回答済みとして登録したい, so that 新しく使うアカウントでも同じアンケートに答え直さずに済む

#### Acceptance Criteria

1. When 開催中のアンケートについて回答済みとしての登録が求められたとき、the アンケート API shall 現在のアカウントを回答済みとして登録し、内容のない成功で応答する
2. When 既に回答済みとして登録されているアカウントについて登録が求められたとき、the アンケート API shall 変更を加えず、同じ成功で応答する
3. The アンケート API shall 回答済みとしての登録で、回答の内容を受け取らず、回答を保存しない
4. The アンケート API shall 回答済みとしての登録をデータの保管先への書き込み 1 回で行う

### Requirement 5: 回答の検証

**Objective:** As a 運営者, I want 設定に沿った完全な回答だけを受け付けたい, so that 集計できない回答や、未完了の回答が混ざらない

#### Acceptance Criteria

1. The アンケート API shall 回答を、質問ごとの選択結果の集まりとして受け取る
2. If 回答が、アンケートのすべての質問に対する選択を含まないとき、then the アンケート API shall 不正な要求として拒否する
3. If 回答が、アンケートに無い質問への選択を含むとき、then the アンケート API shall 不正な要求として拒否する
4. If 質問が単一選択で、選択が 1 つの選択肢でないとき、then the アンケート API shall 不正な要求として拒否する
5. If 質問が複数選択で、選択が空であるか、同じ選択肢を重複して含むか、設定された上限を超えるとき、then the アンケート API shall 不正な要求として拒否する
6. If 選択が、その質問に無い選択肢を含むとき、then the アンケート API shall 不正な要求として拒否する
7. If 回答が「回答しない」の選択肢を 1 つでも含むとき、then the アンケート API shall 未完了の回答として拒否し、何も保存しない
8. If 回答が自由記述など定義にない項目を含むとき、then the アンケート API shall 不正な要求として拒否する

### Requirement 6: 回答の保存と匿名性

**Objective:** As a 利用者, I want 自分の回答が自分のアカウントと結びつかない形で保存されてほしい, so that 安心して正直に答えられる

#### Acceptance Criteria

1. When 検証を通った回答が求められたとき、the アンケート API shall 回答を保存し、内容のない成功（作成）で応答する
2. The アンケート API shall 保存した回答に、アカウントの識別子も、それを復元できる値も、回答者を示すその他の値も持たせない
3. The アンケート API shall 保存した回答に、回答した日（日本標準時の暦）だけを持たせ、日より細かい時刻を持たせない
4. The アンケート API shall 回答済みの利用者を、アカウントの識別子ではなく、アンケートごとに異なる一方向の値で記録する
5. The アンケート API shall 回答済みの利用者の記録に、回答への参照も、回答した時刻も持たせない
6. The アンケート API shall 一方向の値を、秘密の鍵を知らない者がアカウントの識別子から再計算できない方法で求める
7. The アンケート API shall 回答の保存を、回答済みの記録と回答の保存が両方成功するか両方行われないかのどちらかになる 1 回の操作で行う

### Requirement 7: 重複の防止

**Objective:** As a 運営者, I want 同じ利用者から 1 つのアンケートに 1 回しか回答を受け付けたくない, so that 集計が重複で歪まない

#### Acceptance Criteria

1. If 既に回答済みとして記録されているアカウントが回答を求めたとき、then the アンケート API shall 競合として拒否し、新しい回答を保存しない
2. If 同じアカウントが同時に複数の回答を求めたとき、then the アンケート API shall そのうち 1 つだけを保存し、残りを競合として拒否する
3. When 回答済みとしての登録だけを済ませたアカウントが回答を求めたとき、the アンケート API shall 競合として拒否する
4. When 別のアカウントが同じ端末から回答を求めたとき、the アンケート API shall そのアカウントがまだ回答していなければ、回答を保存する
5. The アンケート API shall 重複の判定のために、回答の保存の前に別の読み取りを行わない

### Requirement 8: 保持期限による削除

**Objective:** As a 運営者, I want 保持期限を過ぎたデータが自動で消えてほしい, so that 回答者のデータを必要以上に保持しない

#### Acceptance Criteria

1. When アンケートの終了時刻を過ぎたとき、the アンケート API shall そのアンケートの回答済みの利用者の記録を、次の削除の実行で削除する
2. When アンケートの終了時刻の 1 か月後（日本標準時の暦）を過ぎたとき、the アンケート API shall そのアンケートの回答を、次の削除の実行で削除する
3. The アンケート API shall 削除を、既存の毎分の定期実行のうち、1 日 1 回の日本時間の午前 3 時の枠でだけ行う
4. The アンケート API shall 削除の対象を、設定にあるアンケートのうち保持期限を過ぎたものに限り、開催中や未開催のアンケートのデータを削除しない
5. If 設定を取得できないか、設定にアンケートが無いとき、then the アンケート API shall データの保管先に触れずに削除を終える
6. If 削除の途中で失敗が起きたとき、then the アンケート API shall 失敗を記録し、予約投稿の定期実行と、ほかのアンケートの削除に影響を与えない
7. While 削除済みのアンケートが設定に残っているとき、the アンケート API shall 削除の実行を繰り返しても、結果もデータの保管先への負荷も実質的に変えない
8. If 日次の枠の実行が失敗したとき、then the アンケート API shall 翌日の同じ枠で、期限を過ぎたデータを削除する

### Requirement 9: 運用上の制約

**Objective:** As a 運営者, I want 無料枠の範囲で運用したい, so that アンケートの実施が費用と性能の問題を起こさない

#### Acceptance Criteria

1. While 利用者が回答済みの確認・登録・回答の保存のいずれも求めていないとき、the アンケート API shall データの保管先に一切触れない
2. The アンケート API shall 1 回の要求あたりの処理を、無料枠の CPU 時間の上限に収まる範囲に保ち、Bluesky 連携の重いライブラリを読み込まない
3. The アンケート API shall 回答の保存を、データの保管先への 1 回の呼び出し（書き込みは回答済みの記録と回答の 2 行）で行う
4. The アンケート API shall 秘密の鍵の値を、応答・ログ・保存したデータのいずれにも含めない

### Requirement 10: 秘密の鍵の用意

**Objective:** As a 運営者, I want 回答を匿名にするための鍵が各環境に自動で用意されてほしい, so that 手作業なしに開発・検証・本番でアンケートを実施できる

#### Acceptance Criteria

1. When 配備の際に秘密の鍵が未登録のとき、the 配備の手順 shall ランダムな値を生成して登録する
2. When ローカルでの開発の準備を行うとき、and 秘密の鍵が未設定のとき、the 準備の手順 shall ランダムな値を生成して書き込む
3. While 秘密の鍵が登録済みのとき、the 配備と準備の手順 shall 値を上書きしない
4. The 配備の手順 shall 同じデータの保管先を共用する環境（develop と、そのプレビュー）に同じ値を登録する
5. If 同じデータの保管先を共用する環境の片方にだけ鍵が登録されているとき、then the 配備の手順 shall 値を作り直さず、手動の対処が必要なことを示して失敗で終える
6. The アンケート API shall 秘密の鍵を、予約投稿の暗号鍵とは別の値として扱う
7. When 配備が行われるとき、the 配備の手順 shall 回答を保存するための構造（回答済みの記録と回答）が用意された状態にする
