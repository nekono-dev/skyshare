# Brief: survey-results-public

## Problem

アンケートに答えた利用者や興味のある人が、結果を見られない。結果は運用者が公開を決めたものだけを、OSS 本体には持たず、運用者の R2 から拾って出したい。R2 を持たない運用者（フォークを含む）には、機能ごと無効にできる必要がある。

## Current State

- アンケートの結果を返す API・画面は無い。
- ログイン前の画面は `src/pages/login.astro`（`prerender = true`、静的出力）。ダッシュボード（`/` など）はログイン後の画面。
- アンケート設定の有無でビルド・実行時の動きを切り替える前例がある（`PUBLIC_SURVEY_CONFIG_PRESENT`、`src/lib/site/surveyPresence.ts`）。
- 既存の `/v2/surveys/{surveyId}/…` は認証が必要な API。コレクションの `GET /v2/surveys` は無い。

## Desired Outcome

- R2 バインディングがあるとき（アンケート機能は D1 と R2 を前提とする。R2 が無い環境ではアンケート機能全体が無効で、判定は `survey-results-aggregation` が所有する）、`GET /v2/surveys`（認証なし）が、公開に切り替えられた結果を実施時期の新しい順に返す（ユーザーの決定 2026-11-12）。非表示のアンケートは返さない（ファイルには残る）。
- `/surveys` ページ（ユーザーの決定 2026-11-12）に、アンケートごとに「実施時期・質問の題・選択肢・割合のグラフ」の塊（コンポーネント。アンケート全体の題・説明は出さない）を、実施時期の新しい順に並べて表示する。数字（件数・回答者数）は出さず、割合だけを出す。
- login 画面から `/surveys` へ行ける。ダッシュボードには出さない。
- R2 が無ければ機能ごと無効になる: API・ページは 404、login 画面にリンクを出さない（アンケート全体が無効のため）。
- 取得に失敗したときは、画面が失敗を利用者に分かる形で示し、login 画面の他の機能を妨げない。

## Approach

Worker が R2 の目録と各統計ファイルを読み、共有のスキーマ（`survey-results-aggregation`）で検証し、公開のものだけを新しい順に返す。ブラウザは Worker の API だけを呼ぶ。画面はアンケート 1 件を 1 つのコンポーネント（実施時期・題・説明・質問ごとの選択肢と割合のグラフ）として作り、一覧に並べる。日本語・英語の両方に対応し、既存の UI 部品を使う。

## Scope

- **In**: R2 バインディングの有無の判定（機能の入口の 1 箇所）、`GET /v2/surveys`、取得・検証・失敗時の扱い、必要ならキャッシュ、`/surveys` ページ、結果の塊のコンポーネント（グラフを含む）、login 画面のリンク、API の定義（`src/lib/api/schema`）、辞書（ja・en）、プライバシーポリシーの記述の更新（`help-privacy` への追補）。
- **Out**: 集計・統計ファイルの作成・公開の切り替え（`survey-results-aggregation`）、アンケートの回答・保存（`surveys`）、ダッシュボードからの導線。

## Boundary Candidates

- 取得と検証（R2 の読み取り・スキーマ検証・可視と並びの適用・失敗の扱い）と API
- 画面（`/surveys` の一覧、結果の塊のコンポーネント、割合のグラフ、空の状態）
- オプトアウトの判定と login のリンクの出し分け

## Out of Boundary

- 統計の集計・公開の切り替え・R2 への書き込み
- 質問の定義・回答の保存・保持期限
- ログイン処理・セッション

## Upstream / Downstream

- **Upstream**: `survey-results-aggregation`（統計ファイルの形式・バインディング・機能の有効・無効の判定）、`platform-runtime`（バインディングの型・ミドルウェア・サイト設定）、`api-contract`（API の定義と標準エラー）、`i18n`、`ui-primitives`。
- **Downstream**: なし。

## Existing Spec Touchpoints

- **Extends**: `help-privacy`（結果を公開することと範囲をプライバシーポリシーに書くか、設計で判断する）。
- **Adjacent**: `surveys`（`/v2/surveys` の名前空間を共有。認証なしの `GET` はコレクション 1 本だけ）、`session-accounts`（login 画面の所有）、`platform-runtime`。

## Constraints

- login 画面は静的出力のため、リンクの出し分けはビルド時の旗（R2 バインディングの有無。`survey-results-aggregation` が定める）か、実行時の取得かを設計で決める。
- `GET /v2/surveys` は認証なしで公開される。応答に個別の回答・運用者の内部情報を出さない。
- 並び順は、実施時期の新しい順（開始時刻の降順、同じなら終了時刻の降順）。API と画面のどちらが並べるかは設計で決める（API が並べ、画面は順序を保つのが基本）。
- ログ・エラーに取得した本文を出さない。
- 既存の API の規約（OpenAPI の定義・標準エラー応答・コメントの基準）と UI 部品の規約に従う。

## 画面デザインの合意（必須の工程）

画面のデザインは、設計の前に、アーティファクトで選択肢を見せながら利用者と合意する（ユーザーの決定 2026-11-12）。`/kiro-spec-batch` の前に行い、合意の内容を次の節に書く。

合意する項目: 一覧のレイアウト（カードの構成）、割合のグラフの形（横棒など）、実施時期の表記、空の状態（公開された結果が無いとき）、取得失敗の表示、login 画面のリンクの位置と文言、スマホ幅での見え方。

デザイン案（クラウドのアーティファクト、2026-11-12 作成）: https://claude.ai/artifact/XvR5BLKHV7woYkuCCKRRfj 。決定欄の記入内容を、次の「合意の結果」に転記する。

### 合意の結果

合意した画面イメージ（アーティファクト、2026-11-12）: https://claude.ai/artifact/TdpnNtVXFCxp2sEiAC4v9d （login 画面・`/surveys` 一覧・スマホ幅の既定案）。

利用者の決定（2026-11-12、アーティファクトの案から選択）:

- **グラフ**: B と C を合わせた形。左側に選択肢の題（ラベル）、右側に割合付きのグラフ（割合は棒の中に表示）。割合の数字だけを出し、件数は出さない。
- **カード**: A 枠付きカード（実施時期・アンケート文章・質問と選択肢のグラフを 1 つの枠にまとめる）。
- **login のリンク**: B 文中の小リンク（ボタン風にしない）。
- **色**: 色のトークンは、既存の共通のスタイルトークン（`src/styles/tokens.css`）と共通コンポーネントを使い、新しい色を定義しない。最も割合の大きい選択肢だけをプライマリ色（ブランドの色。既存のトークンのうち対応するものを設計で選ぶ）、そのほかの選択肢は、背景と混ざらない灰色の共通トークン（候補: `--color-gray-hover`。棒の下地は `--color-gray`。`--color-muted` は背景と混ざるため使わない。利用者の決定 2026-11-12）にする。複数の選択肢が同率で最大なら、いずれもプライマリ色にする（設計で確認）。
- **アンケート全体の題・説明は出さない**: カードは「実施時期＋質問ごとの題・選択肢・グラフ」で構成する。
- **複数選択の注記は出さない**（「合計は 100% を超えることがあります」の文言は不要）。
- **スマホ幅**: 1 列。選択肢の題を棒の上に置く（合意済み）。
- 未合意（既定は推奨案。設計で確認する）: 時期の表記（既定: `2026/09/01 〜 09/30`）、空の状態・取得失敗の文言と再読み込み。
