# Brief: survey-results-aggregation

## Problem

アンケートの回答は D1 に匿名で保存され、終了の 1 か月後に削除される。結果を利用者へ公表するには、回答を集計して残す手段が要る。集計結果を OSS の資材（Git・ビルド生成物）に混ぜると、運用ごとの結果が OSS に入り込む。また、結果を公表するかどうかは運用者が決めたい（公表し忘れより、出し忘れのほうが安全）。

## Current State

- 回答の保存: D1 の `survey_answers`（did を持たず、回答日と回答の JSON だけ）。回答済みの集合 `survey_respondents` は終了時刻以後に削除、回答は終了の 1 か月後に削除（`src/lib/survey/retention.ts`、Worker の日次の後片付けから起動）。
- 回答の形: `src/lib/survey/answers.ts` の `NormalizedAnswers`（質問 ID → 選択肢 ID か、その配列）。「回答しない」を含む回答は保存されない。
- 質問の定義は `SURVEY_CONFIG`（`src/lib/survey/definition.ts`）。
- R2 の前例: `SCHEDULE_IMAGES` バインディング（`wrangler.jsonc`）。

## Desired Outcome

- **アンケート機能は D1 と R2 を前提とする**（ユーザーの決定 2026-11-12）。R2 バインディングが無い環境では、アンケート機能全体を使えない（提示・回答・結果のすべてが無効）。以前の「R2 が無ければ従来の保持期限で動く」案は取り下げた。
- アンケートの実施期間（終了時刻）を過ぎたら、日次の後片付けの枠で自動的に集計し、統計ファイルを R2 バインディングへ書く。
- 統計ファイルへの保存が成功した後に、同じ処理で D1 のそのアンケートの回答と回答済みの集合を削除する。失敗したら削除せず、翌日に再試行する。**回答の削除の契機は、集計の保存の成功後だけ**（「終了の 1 か月後」の保持期限は廃止する）。
- 統計ファイルは、アンケートごとの結果（実施期間・質問の題・選択肢・割合。アンケート全体の題・説明は持たない）と、目録（一覧）からなる。割合だけを持ち、件数・回答者数は持たない。
- 集計時のアンケートは常に非表示で作る。公開・非公開の切り替えは、`npm run survey` のサブコマンドが R2 の可視フラグを書き換える（切り替えの CLI は `survey-operations` が所有する）。
- 統計ファイルは OSS の資材に入らない。

## Approach

Worker の日次の後片付けの枠（既存の `runSurveyRetention` に代わる入口）で、終了済み・未集計のアンケートを集計して R2 に書き、成功後に D1 を削除する。統計ファイルには、設定から消えても表示できるよう、アンケートの期間と、質問の題・選択肢の文言（ja・en）を複写する。アンケート全体の題・説明は、設定の形式から廃止されるため（`surveys` の更新を参照）持たない。`SURVEY_CONFIG` の形式は変えない。

## Scope

- **In**: 統計ファイルの形式と検証スキーマ（読む側と共有する部品）、集計（質問ごと・選択肢ごとの割合）、集計と削除の手順（保存成功後に削除・失敗時の再試行・冪等）、保持期限の廃止（`retention.ts`・`period.ts` の保持の判定の置き換え）、R2 バインディングが無い環境でのアンケート機能の無効化（実行時の判定とビルド時の旗）、R2 バケットの設定（本番・develop・プレビュー・ローカル）。
- **Out**: 結果ページ・ビルド時の取得（`survey-results-public`）、CLI の体系・運用手順（`survey-operations`）、回答の保存と回答済みの確認（`surveys`。ただし無効化の判定は本 spec が所有し、`surveys` が使う）、R2 バケットの作成（運用者の作業）。

## Boundary Candidates

- 統計ファイルの形式とスキーマ（共有の部品）
- 集計（D1 の回答 → 割合）と、終了後・0 件・複数選択の規則
- 集計と削除の手順（日次の枠から起動。失敗の扱い）
- 機能の有効・無効の判定（D1・R2 の両方があるか）

## Out of Boundary

- 閲覧の API・画面
- CLI のコマンド体系・運用手順
- アンケートの実施・回答の保存（`surveys`）

## Upstream / Downstream

- **Upstream**: `surveys`（D1 のテーブル、回答の形、`SURVEY_CONFIG` の形式）、`platform-runtime`（Worker の `scheduled`・バインディングの型）。
- **Downstream**: `survey-results-public`（統計ファイルの形式を、ビルド時に読む）、`survey-operations`（統計ファイルの可視フラグを CLI が書く）。

## Existing Spec Touchpoints

- **Extends**: `surveys`（保持期限の規則を「集計の保存の成功後の削除」に置き換える。提示・回答の API は R2 が無いと無効になる）。
- **Adjacent**: `ops-config-secrets`・`ops-tooling-layout`（`wrangler` の設定・R2 バケットの設定の同期）、`platform-runtime`。

## Constraints

- 割合の分母は、そのアンケートの回答者数。複数選択の質問は「その選択肢を選んだ回答者の割合」で、質問の合計は 100% を超えうる。小数点は 1 桁（ユーザーの決定 2026-11-12）。
- 回答が 0 件のアンケートは、統計ファイルに入れない。削除は行う。
- しきい値による伏せ字は設けない（ユーザーの決定 2026-11-12）。回答数が少ないと個人が推測されうる点は、運用者が公開の切り替えで判断する。
- 統計ファイルに、個別の回答・回答日・回答者の値・件数・回答者数を入れない。
- 実行は終了時刻の後に限る。日次の枠のため、終了から最大 1 日遅れる。
- 集計は、アンケートが `SURVEY_CONFIG` にある間に行う（質問の文言の複写に設定が要る）。設定から除去してよいのは集計済みのものだけ（`survey-operations` の `prune`）。
- 冪等: 既に統計ファイルがあれば再集計せず（上書きしない）、D1 の削除だけを行う。同時実行は、R2 の条件付き書き込みで防ぐ。
- 失敗の記録は例外の種類の名前だけ（回答・本文をログに出さない）。1 件の失敗が他のアンケートの集計を止めない。
- 回答済みの集合（`survey_respondents`）の削除の時機は、現行の「終了時刻以後」を保つか、回答と同時（集計の保存の成功後）にするかを設計で決める。匿名性の観点では、できるだけ早く消す現行の規則を保つほうが安全で、既定はこちら。
- ビルド時の旗（`PUBLIC_SURVEY_CONFIG_PRESENT`）は、R2 バインディングの有無も条件にするかを設計で決める。静的な login 画面と提示の入口が、R2 の無い環境でアンケートを出さないようにする。
- 統計ファイルの読み手は、ビルド時の取得（`survey-results-public`）と CLI（`survey-operations`）。Worker は書くだけで、実行時に読んで返すことはしない。
- 設計で決める: R2 のオブジェクトの構成（目録 1 つ＋アンケートごと、可視フラグの置き場。CLI が書き換えるため、小さく独立して書き換えられる形にする）、バインディングの名前、環境（本番・develop・プレビュー）ごとのバケット。
