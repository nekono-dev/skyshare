- [ ] 2. Core: 形式・集計・保管・有効判定
- [x] 2.1 統計ファイルの形式と検証の規則を定める
  - 結果・目録・可視フラグの 3 種の形式と版、R2 のオブジェクトの構成（キー名）を 1 つの検証の規則として定め、書く側と読む側が同じものを使えるようにする
  - 定義にない項目（件数・回答者数・回答日・アンケート全体の題・説明など）を拒否する。割合の範囲と桁、識別子の重複、未知の版も拒否する
  - 検証の結果は成否だけを返し、読んだ本文を失敗の内容に含めない
  - 旗が無い・不正なときは非表示として扱う読み手の規則を、同じ場所に定める。純粋関数 `resultMatchesIndexEntry(entry, result): boolean`（id・opensAt・closesAt が目録の記録と一致するとき真）と `isVisible(visibility: SurveyVisibility | undefined): boolean`（undefined や visible が true でないとき偽）を export する。`survey-results-public`（ビルド）と `survey-operations`（publish・status）は、読み手の規則の単一の実装としてこの 2 つを使う
  - ビルドとコマンドラインから読み込めるよう、Worker 専用の部品に依存させない
  - 完了の状態: 正常な 3 種は通り、未知の項目・未知の版・範囲外の割合・重複を含むものは拒否されることが単体テストで確かめられている。`resultMatchesIndexEntry` と `isVisible` の真偽の境界も単体テストで確かめられている
  - _Boundary: results/schema.ts_
  - _Requirements: 4.1, 4.2, 4.4, 4.5, 4.6, 4.7, 5.2, 5.3_

- [x] 2.2 回答から結果を求める集計の規則を実装する
  - 設定のアンケートと回答の本文から、選択肢ごとの割合（回答者数が分母、小数点以下 1 桁、四捨五入）を求める
  - 複数選択は選択肢ごとに独立に求め、「回答しない」の選択肢は結果に含めない。しきい値による伏せ字や合計の補正はしない
  - 読めない行・設定に合わない行・「回答しない」を含む行は回答者に数えない。回答者が 0 なら結果を作らない
  - 質問の題・選択肢の文言を設定から複写し、アンケート全体の題・説明は含めない
  - 完了の状態: 単一選択・複数選択・0 件・除外される行・丸めの境界の単体テストが通り、出力が 2.1 の検証を通る
  - _Depends: 2.1_
  - _Boundary: results/tally.ts_
  - _Requirements: 3.1, 3.2, 3.3, 3.4, 3.5, 3.6, 3.7, 4.3_

- [x] 2.3 結果の保管と既存本体の検証を実装する
  - `readResult(bucket, surveyId)` は本体を読み、JSON・形式・要求した識別子を検証する。無ければ `undefined`、不正や読み取り失敗は本文を含めず例外にする
  - `readMatchingResult(bucket, expected: {id, opensAt, closesAt})` は読み取った結果を期待値と照合し、不一致は `ResultMismatchError` にする。照合規則は既存の `resultMatchesIndexEntry` と同じ
  - `putResultOnce` の `exists` は保存確認とせず、必ず `readMatchingResult` で確認してから先へ進む。目録の比較交換は最大 3 回
  - 完了の状態: 本体の検証・識別子と期間の照合・`exists` 後の読み直し・上書き禁止・目録比較交換を route テストで確かめる。不正・不一致の本文はログや例外に含めない
  - _Depends: 1.1, 1.2, 2.1_

- [ ] 3.2 本体の検証・集計・保存後の回答削除を実装する
  - 目録に記録があればその識別子と期間を期待値として本体を検証する。目録が無く設定だけがある場合は設定の識別子と期間を期待値にする。本体だけが既存なら検証後、本体の値で目録を補う
  - 本体が無ければ回答を batch で読み集計する。目録が `result` なのに有効回答が 0 件なら不整合として回答を残す。目録が無く 0 件なら `empty` を記録する。有効回答があれば結果を上書き禁止で保存する。`exists` や競合の後は本体を読み直して検証する
  - 本体の不正・不一致は上書きせず、回答を削除対象に加えない。復旧保存・保存確認に失敗した識別子は同じ実行の本流・掃除のどの削除経路にも渡さない
  - 結果と目録の記録を確認できた識別子だけをまとめて削除する。可視フラグには書かない
  - 完了の状態: route テストで正常保存後だけ削除、0 件は empty 記録後に削除、本体のみ既存なら検証後に目録補完、不正・不一致は回答を残す、`exists` の後も検証、復旧保存失敗後に掃除でも回答が消えない、再実行で上書きしないことを確かめる
  - _Depends: 1.4, 2.2, 2.3, 3.1_
  - _Boundary: daily.ts_

- [ ] 3.2a 設定から外れた終了済みの残存回答を掃除する

  - `result` は本体を検証してから、`empty` は検証済み目録を根拠に削除する。残っている識別子の回答行と回答済みの集合の行を削除する。本体が無い・不正・不一致なら回答を残し、再集計しない。設定自体が無くても掃除する
  - 削除は batch でまとめ、グループごとに失敗を分け、識別子と例外の種類の名前だけを記録する。同じ実行内では再試行しない。目録の追記はしない
  - 完了の状態: route テストで候補の選び方と残存確認、result・empty の検証条件、回答と集合の削除、本体欠落で残すこと、設定にある識別子を扱わないこと、空の batch を送らないこと、削除失敗後も後続処理、201 件目以降が古い識別子として滞留することを確かめる
