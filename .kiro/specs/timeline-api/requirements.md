# Requirements Document

## Introduction

自分の投稿の一覧を、スレッドの構造を確定させたグループの単位で返し、取得元の一覧に欠けがあっても自分のスレッドを完全な形で表示できるようにする。

## Boundary Context

- **In scope**:
  - 自分の投稿の一覧の取得とページング。
  - スレッドのグループ化と、表示する系統の選出。
  - 取得元の一覧から欠けた投稿の補完。
  - 投稿に紐づくentryの付与。
- **Out of scope**:
  - 一覧の画面での表示。
  - entryの作成の可否の判断。
- **Adjacent expectations**:
  - なし

## Requirements

### Requirement 1: 自分の投稿の一覧

**Objective:** As a 利用者, I want 自分の投稿だけを新しい順に見たい, so that 自分の発信を振り返れる

#### Acceptance Criteria

1. When 一覧が要求されたとき、the 一覧 API shall 自分の投稿を新しい順に返し、リポストと、他人の投稿を起点とするスレッドに属する投稿を返さない
2. The 一覧 API shall 1ページあたりの取得件数とカーソルによるページングの方式を、グループ化によって変えない（1ページ目が指定件数に満たない場合はカーソルをたどって追加のページを取得する。追加取得は1回の要求あたり最大5ページまで）
3. The 一覧 API shall 一覧の応答を、確定済みのスレッドグループの配列の形で返す

### Requirement 2: スレッドグループ

**Objective:** As a 利用者, I want 自分のスレッドをひとまとまりで見たい, so that 一連の投稿として把握できる

#### Acceptance Criteria

1. The 一覧 API shall 自分を起点とするスレッドの、自分の投稿の直線的な連鎖を1つのスレッドグループとして、起点の投稿と古い順の後続の投稿で返す
2. When スレッドが分岐しているとき、the 一覧 API shall 分岐点では直前の投稿との投稿日時の差が最も近い1系統を採用し、候補が1件の分岐点では投稿日時によらず採用する
3. The 一覧 API shall 分岐点で採用しなかった系統の投稿を、単独の投稿としても返さない
4. The 一覧 API shall 系統の選出を一覧の取得のたびにやり直し、採用した系統を保存しない（採用した系統の投稿が削除されると、次の取得で別の系統が採用される）
5. The 一覧 API shall スレッドの構造の判定をサーバーの1つの実装だけで行い、クライアントでの返信の連鎖の再構築を0件にする

### Requirement 3: 欠けた投稿の補完

**Objective:** As a 利用者, I want 取得元の一覧に欠けがあってもスレッドを完全に見たい, so that 途中の投稿が抜けない

#### Acceptance Criteria

1. If 取得元の一覧からスレッドの投稿が欠けているが起点の投稿を取得できるとき, then the 一覧 API shall 欠けた投稿を別途取得して補う（後続がすべて欠けていても、中間が欠けていても補う）
2. If 起点の投稿が取得元の一覧に無いとき, then the 一覧 API shall その起点の投稿の日時に基づく位置に、新しい順を保って挿入する
3. If スレッドの取得に失敗したとき, then the 一覧 API shall 自分が起点の投稿だけを単独の投稿として返し、返信の投稿は返さない
4. When 取得済みの一覧だけでスレッドの構成を確定できるとき（各投稿の返信数が一覧にある自分の返信の件数と一致するとき）、the 一覧 API shall そのスレッドの個別取得を行わず、取得した場合と同じ系統を選ぶ
5. If 返信数が一覧にある自分の返信の件数と一致しないとき, then the 一覧 API shall スレッドを個別に取得して欠けた投稿を補う

### Requirement 4: entry の付与

**Objective:** As a 利用者, I want 投稿に紐づく entry を一覧で見たい, so that 共有済みの投稿が分かる

#### Acceptance Criteria

1. The 一覧 API shall 各投稿に、その投稿を派生元とする自分の entry を、派生元の URI で突き合わせて付与する
2. The 一覧 API shall 付与する entry の取得で、表示する投稿のいちばん古い日時の1日前より古いレコードだけのページを取得した時点で、そのページの次を取得しない
3. When 補完で取得した起点の投稿が一覧より古いとき、the 一覧 API shall その投稿に紐づく entry も付与する
