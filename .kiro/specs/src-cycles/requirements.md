# 要件書

## 概要

`lib` 内の循環 import と、`lib` 内の領域どうしの双方向の依存を解消する。依存の向きを一方向にし、循環を取り除く。利用者に見える振る舞い（翻訳の文言と言語の判定、旧形式の共有設定の移行結果、Bluesky レコードの形、Entry の表示）は変えない。

2026-11-01 の実測:

- ファイル単位の循環（型だけの import を含む）: 2 件、計 18 ファイル。`lib/i18n` の翻訳の型と辞書の循環（16 ファイル）と、`lib/settings` の旧形式の移行処理と共有設定の循環（2 ファイル）。
- `lib` 内の領域どうしの双方向の依存: 7 組（`lib/api` ↔ `lib/video`・`lib/atproto`・`lib/feedback`・`lib/survey`、`lib/atproto` ↔ `lib/entry`、`lib/entry` ↔ `lib/timeline`・`lib/image`）。

用語:

- **領域**: `src/lib/<領域>/`。
- **双方向の依存**: ある領域の file が別の領域の file を import し、その逆も成り立つ状態。

## 境界の文脈（任意）

- **対象内**: `lib/i18n` の翻訳の型と辞書の循環の解消。`lib/settings` の移行処理と共有設定の循環の解消。`lib` 内の 7 組の双方向の依存の解消。依存の向きの規約の steering への明記。検査の許容リストから循環の項目を消すこと。
- **対象外**: 翻訳の文言、設定の保存形式、Bluesky レコードの形、Entry の表示（振る舞いは変えない）。`components` の循環（`ThreadComposer` と `SuggestPopover`・`VideoPicker` の 2 組）。`src/` 直下のファイル（`env.ts`・`vars.ts`）との依存の双方向（3 組）。`lib` の UI 依存（`src-lib-ui-boundary`）。`pages` の責務（`src-pages-thin`）。
- **隣接する期待**: `src-import-rules` の検査は、ファイル単位の循環を検出する。ディレクトリ単位の双方向の依存を検出する規則は現在ない。その規則を追加するには、`src-import-rules` の要件の改訂と steering の改訂が要る（この spec の範囲外）。`i18n`・`settings`・`atproto-records`・`entry-sharing` の振る舞いは、それぞれの spec が所有する。

## 要件

### 1. 翻訳の型と辞書の循環

**目的:** 開発者として、翻訳の型と辞書の間に循環が無いことを知りたい。どちらを先に読めばよいかが分かるようにするため。

#### 受入基準

1. The `lib/i18n` shall モジュール間の循環 import（型だけの import を含む）を含まない。
2. When 翻訳の文言が要求されたとき, the 翻訳 shall 循環を解消する前と同じ文言と言語の判定の結果を返す。

### 2. 旧形式の共有設定の移行処理と循環

**目的:** 開発者として、移行処理と共有設定の間に循環が無いことを知りたい。移行処理の読み方が一つに決まるようにするため。

#### 受入基準

1. The `lib/settings` shall モジュール間の循環 import（型だけの import を含む）を含まない。
2. When 旧形式の共有設定が読み込まれたとき, the 設定 shall 循環を解消する前と同じ移行結果を返す。

### 3. `lib` 内の領域どうしの双方向の依存

**目的:** 開発者として、`lib` 内の領域の依存を一方向にしたい。変更の影響が一方向に伝わり、領域の関係が読めるようにするため。

#### 受入基準

1. The `lib` の領域 shall 互いに双方向の依存を持たない。
2. When 依存の向きを変えたとき, the 変更 shall Bluesky レコードの形と Entry の表示内容を変えない。

### 4. 振る舞いと既存の検証の不変

**目的:** 利用者として、依存の整理で画面や API の振る舞いが変わらないでほしい。機能が壊れていないと分かるようにするため。

#### 受入基準

1. The 変更 shall 利用者に見える画面と API の振る舞いを変えない。
2. The 既存のテストスイート shall 変更の前と同じく全件通過する（272 件）。

### 5. 検査と規約への反映

**目的:** 開発者として、循環の解消が検査の結果と規約に現れてほしい。解消を確かめられ、規約が後戻りしないようにするため。

#### 受入基準

1. When 循環の解消が完了したとき, the 許容リスト shall 循環の項目（ファイル単位）を 0 件にする。
2. The ステアリング（`structure.md`） shall `lib` の領域の間の依存の向きの規約を明記する。
