# Implementation Plan

- [x] 1. URL の生成
- [x] 1.1 投稿・画像・entry の URL を一貫した形式で生成する
  - 投稿者の識別子と投稿のキーから投稿ページの URL と entry の相対パスを返す
  - リポジトリの DID と参照を符号化した画像の URL を返す
  - サイトの URL を前置した entry の絶対 URL を返す
  - 完了条件: 4 種類の生成結果が期待どおりの文字列になることを単体テストで確認できる
  - _Boundary: UrlGenerator_
  - _Requirements: 1.1, 1.2, 2.1, 2.2_

- [x] 2. AT URI の分解と検証
- [x] 2.1 AT URI をリポジトリ・コレクション・キーに分解する
  - 正しい形式なら 3 要素を返し、形式が不正な文字列では結果を返さない
  - 完了条件: 正常な URI の分解結果と、セグメント不足の文字列が結果なしになることを単体テストで確認できる
  - _Boundary: AtUriParser_
  - _Requirements: 3.1, 3.2_

- [x] 2.2 キーに特殊文字を含む AT URI を拒否する
  - キーに疑問符またはシャープを含む URI では結果を返さない
  - 完了条件: 該当する URI が結果なしになることを単体テストで確認できる
  - _Boundary: AtUriParser_
  - _Requirements: 3.3_

- [x] 2.3 期待するコレクションと所有者の AT URI だけを受け付ける
  - 分解結果のコレクションとリポジトリがどちらも期待どおりのときだけ結果を返す
  - コレクション不一致、他人の URI、形式不正はいずれも結果を返さない
  - 完了条件: 一致・コレクション不一致・所有者不一致・形式不正の 4 通りの返り値を単体テストで確認できる
  - _Boundary: OwnerCheck_
  - _Depends: 2.1_
  - _Requirements: 4.1, 4.2, 4.3, 4.4_

- [ ] 3. blob 参照からの画像 URL
- [x] 3.1 blob 参照から識別子を取り出す
  - 文字列はそのまま、リンクを持つオブジェクトはその値を識別子として返し、取り出せない値では識別子を返さない
  - 完了条件: 文字列・リンクを持つオブジェクト・null・未指定の各入力の返り値を単体テストで確認できる
  - _Boundary: BlobImageUrl_
  - _Requirements: 5.1, 5.2, 5.3_

- [x] 3.2 blob から画像の URL を得る
  - 識別子を取り出せる blob からは画像の URL を返し、blob が無い、または識別子を取り出せないときは結果を返さない
  - 完了条件: 正常な blob、blob 未指定、参照が解決できない blob の返り値を単体テストで確認できる
  - _Boundary: BlobImageUrl_
  - _Depends: 1.1, 3.1_
  - _Requirements: 5.4, 5.5_
