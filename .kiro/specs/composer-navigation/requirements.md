# Requirements Document

## Introduction

投稿フォームで作成中の内容を、別のページへ移る操作で失わないようにし、予約投稿が無効のときは有効にする設定へ迷わず移れるようにする。

## Boundary Context

- **In scope**:
  - 作成中に別のページへ移ろうとしたときの、下書き保存の確認。
  - 予約投稿が無効のときにカレンダーのボタンを押したときの、設定への案内。
- **Out of scope**:
  - 下書きの保存の API と、下書きの一覧の表示。
  - ブラウザの戻る・進む、タブを閉じる、再読み込みでの確認。
  - 設定のページでの予約投稿の有効化の操作。
- **Adjacent expectations**:
  - なし

## Requirements

### Requirement 1: 未保存の内容の保護

**Objective:** As a 利用者, I want 作成中の内容を別のページへ移っても失いたくない, so that 書きかけの投稿を安心して残せる

#### Acceptance Criteria

1. When 未保存の本文があるときに別のページへ移ろうとしたとき、the 投稿フォーム shall 遷移を止め、下書きを保存して移る・破棄して移る・編集を続けるの3択を出す
2. When 破棄して移るが選ばれたとき、the 投稿フォーム shall 下書きの保存を呼ばずにページへ移る
3. When 編集を続けるが選ばれたとき、the 投稿フォーム shall ページへ移らず本文を残す
4. If 本文が空である、または開いた下書きから変更がないとき, then the 投稿フォーム shall 確認を出さずにそのまま移る
5. While 3択の確認が出ているとき、the 投稿フォーム shall 遷移先のページを表示する回数を0にし、表示中のページの住所を変えない

### Requirement 2: 予約投稿が無効のときの案内

**Objective:** As a 利用者, I want 予約投稿が使えないときに有効にする方法へ迷わず移りたい, so that 設定を探さずに予約を始められる

#### Acceptance Criteria

1. When 予約投稿が無効のときにカレンダーのボタンが押されたとき、the 投稿フォーム shall 設定で有効にする案内を出し、設定を開くが選ばれたら設定のページへ移る
2. When 本文があるときに案内の設定を開くが選ばれたとき、the 投稿フォーム shall 移る前に3択の確認を出す
