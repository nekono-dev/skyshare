# Implementation Plan

- [ ] 1. 基盤: 文言・端末の記録・回答の状態・検証用の設定
- [x] 1.1 (P) アンケートの画面の固定の文言を、日本語と英語で用意する
  - 送信、「回答しない」を含む状態での閉じる操作、回答が匿名で保存され取り消せない旨、すべての質問に答えると送信できる旨、「回答しない」を選ぶと送られず次の起動でもう一度聞く旨、送信の失敗と再送信の案内の文言を作る
  - 既存の画面の文言と同じ仕組みに結合し、日本語を正本として英語が同じ項目を持つことを型で強制する。アンケートの質問・選択肢・タイトルの文言は持たない
  - 完了: 日本語と英語の項目が一致することを既存の検査が確認し、画面から両言語で引ける
  - _Boundary: SurveyMessages_
  - _Requirements: 3.9, 6.1, 6.3_
- [x] 1.2 (P) 端末の記録とタブごとの辞退の読み書きを作る
  - アンケートごとに「回答済みかどうか」と「記録済みのアカウント」を端末に保持し、アカウントは重複なく加える。タブごとの辞退は、そのタブの間だけ有効な別の記録として持つ
  - 記録が無い・壊れている・形が違う・保存先が使えないときは「記録なし」として扱い、書き込みの失敗も含めて例外を外へ出さない
  - 保存するのは回答済みの旗とアカウントの識別子だけで、回答の内容と時刻を保存しない
  - 完了: 未保存・壊れた内容・保存先の例外・書き込みの例外・重複したアカウントの追加・辞退の読み書きを確認する単体テストが通り、保存内容に回答の内容と時刻が無いことをテストで確認する
  - _Boundary: SurveyDeviceRecord_
  - _Requirements: 2.1, 2.8, 2.9, 2.10, 4.3, 5.5, 5.6_
- [x] 1.3 (P) ダイアログの選択状態の補正・完了の判定・送信本文の組み立てを作る
  - 複数選択で「回答しない」が新たに選ばれたらそれだけにし、他の選択肢が選ばれたら「回答しない」を外す。単一選択は部品の値をそのまま採る
  - すべての質問に 1 件以上の選択があるときを完了とし、いずれかの質問で「回答しない」が選ばれているかを判定する。判定は設定の「回答しない」の印だけで行う
  - 送信本文は、単一は選択肢の識別子、複数は選択肢の並び順の配列とし、利用者の識別子や時刻を含めない
  - 完了: 単一・複数、上限ちょうど、「回答しない」からの切り替えと他の選択肢からの切り替え、未完了と完了、送信本文の形を確認する単体テストが通る
  - _Boundary: SurveyAnswerDraft_
  - _Requirements: 3.4, 3.6, 4.1, 4.8, 5.2, 5.3_
- [ ] 1.4 (P) 検証用の開催中の設定を資材として用意し、検証を通ることを単体テストで保証する
  - アンケート 1 件を、開始は過去、終了は検証の期間中に終わらない遠い将来にする。単一選択（「回答しない」を含む）と複数選択（上限 2、「回答しない」を含む）の質問を持ち、全対応言語の文言を備える
  - 完了: 設定のスキーマの検証を通り、現在時刻で開催中のアンケートとして返り、2 種類の質問・上限・「回答しない」を含むことを確認する単体テストが通る。通らなくなったとき（言語の追加など）にこのテストが失敗する
  - _Boundary: SurveyE2eHarness_
  - _Requirements: 7.2, 7.5_

- [ ] 2. コア: サーバー呼び出し・起動時の判定・ダイアログ
- [ ] 2.1 (P) 回答済みの確認・登録・回答の送信の呼び出しを、画面が扱う結果の分類に正規化する
  - 確認は「回答済み／未回答／終了または無い／失敗」、登録は「登録済み／終了または無い／失敗」、送信は「保存／重複／終了または無い／未認証／失敗」に分ける。想定外の状態コードと通信の例外は失敗にし、例外を外へ出さない
  - 送信の本文は回答だけとし、利用者の識別子や時刻を含めない
  - 完了: 状態コードごとの分類と通信の例外を、生成済みのクライアントをモックした単体テストで確認し、送信の本文に回答以外が含まれないことを確認する
  - _Boundary: SurveyApiClient_
  - _Requirements: 2.2, 2.3, 2.6, 2.7, 4.1, 4.4, 4.5, 4.6, 4.7, 4.8_
- [ ] 2.2 起動時の判定を作る: ページの除外と、端末の記録からサーバーへの確認までの手順
  - プライバシーポリシーのページ（末尾のスラッシュの有無を問わない）とゲスト表示では見送る
  - 端末の記録にアカウントがあれば通信せず何もしない。無くて端末が回答済みなら回答済みとして登録し、成功したらアカウントを記録に加える。無くて端末も未回答ならサーバーに確認し、回答済みなら端末に記録する。サーバーが未回答と明示したときだけ「聞く」を返す
  - 終了または無い・失敗のときは、記録を変えずに何もしない（次の起動で再度判定される）
  - 完了: 記録にあり／端末が回答済み／未記録の 3 経路と、登録・確認それぞれの回答済み・未回答・終了・失敗、ページの除外（プライバシーポリシーの末尾の有無・ゲストの印）を確認する単体テストが通り、記録にあるときに通信しないことを確認する
  - _Boundary: SurveyLaunchCheck_
  - _Depends: 1.2, 2.1_
  - _Requirements: 1.1, 1.3, 1.4, 2.1, 2.2, 2.3, 2.4, 2.5, 2.6, 2.7_
- [ ] 2.3 (P) 回答必須のダイアログを作る
  - アンケートのタイトル・説明・すべての質問と選択肢を現在の表示言語で表示し、言語を切り替えても選択を保つ。質問は既存の選択式の共通部品で描画し、「回答しない」が選ばれている間は上限を渡さない
  - 背景のクリックと Esc では閉じない。キーボードだけで操作でき、タイトルを名前に持つダイアログとして支援技術に伝わる。質問が多いときは内容をスクロールして最後まで到達できる
  - 未完了の間は送信を押せない。「回答しない」を含む間は送信の操作が「閉じる」になり、閉じる操作を通知する。それ以外は回答を通知する。送信中は質問と操作を押せない。取り消せない旨を送信の操作の前に示し、失敗時は失敗の文言を示して選択を保つ
  - 完了: 未完了の間の送信不可、「回答しない」を含む間の「閉じる」の文言と通知、上限、背景と Esc で閉じないこと、言語の切り替えでの選択の保持、設定の言語での文言、送信中の無効化、失敗の文言を確認する単体テストが通る
  - _Boundary: SurveyDialog_
  - _Depends: 1.1, 1.3_
  - _Requirements: 3.1, 3.2, 3.3, 3.4, 3.5, 3.6, 3.7, 3.8, 3.9, 4.1, 4.2, 4.7, 5.1, 5.3, 5.4, 6.2_

- [ ] 3. 統合: 常駐する入口と E2E への供給
- [ ] 3.1 全ページに常駐する入口を作り、基本のレイアウトに組み込む
  - 判定は、ページの除外、設定の取得と開催中の判定、タブの辞退、アクティブなアカウントの取得、起動時の判定の順に行う。設定が無い・取得に失敗した・開催中のアンケートが無い・アカウントが無いときは何も表示せず続行する
  - 除外ページで見送った場合は判定済みにせず、他のページへ移動したときに判定する。同じ画面を開いている間は同じ判定を繰り返さない。ページ遷移でダイアログが消えないようにする
  - 「聞く」ならダイアログを出す。送信は保存・重複なら回答済みとして記録して閉じ、終了・未認証なら記録せず閉じ、それ以外の失敗なら失敗を示して開き続ける。「回答しない」で閉じるときは送信も記録もせず、そのタブの辞退を記録して閉じる
  - 完了: 基本のレイアウトの全ページに入口が置かれ、未ログイン・ゲストでは通信が起きず、辞退したタブでは確認の通信が起きないことが、手元の開発サーバーで確認できる
  - _Boundary: SurveyGate_
  - _Depends: 2.2, 2.3_
  - _Requirements: 1.1, 1.2, 1.5, 1.6, 1.7, 2.5, 4.3, 4.4, 4.5, 4.6, 4.7, 5.4, 5.5, 5.7_
- [ ] 3.2 (P) E2E の実行に、検証用の設定の供給と既定の応答を組み込む
  - E2E の実行が自分で開発サーバーを起動するときに限り、起動の前に検証用の設定を生成して、開催中のアンケートが取得できる状態にする。実行後は、成功・失敗のどちらでも、実行前の環境の設定での生成に戻して通常の状態にする
  - 開発サーバーが既に起動している場合は生成せず、確認側が配信用の設定の有無を事前に確かめられるようにする
  - すべての E2E の画面に、回答済みの確認への既定の応答（回答済み）を登録する。アンケートの確認は同じ宛先を後から登録して上書きできる
  - 完了: 実行の前後で配信用の設定の状態が元に戻ること、検証用の設定が有効な間も、アンケートに関係しない既存の E2E の画面の確認が影響を受けず通ることを確認する
  - _Boundary: SurveyE2eHarness_
  - _Depends: 1.4_
  - _Requirements: 7.1, 7.3, 7.4, 7.6_

- [ ] 4. 検証: 実ブラウザでの確認と全体の検査
- [ ] 4.1 起動時の判定と端末の記録の経路を、ヘッドレスブラウザで操作後の表示として確認する
  - セッションとアンケートの 3 つの操作の応答を差し替え、呼び出しの回数・送信本文・端末の記録も検証する
  - 未回答での起動でダイアログが出て、回答して送信すると閉じて記録され、再読み込みで再確認も再表示もないこと。端末の記録による非表示（通信なし）、端末が回答済みで新しいアカウントのときの登録、確認が回答済みの場合を確認する
  - 確認の終了・失敗ではダイアログが出ず記録も変わらないこと。プライバシーポリシーのページとゲスト表示でダイアログも通信もないこと、プライバシーポリシーから他のページへのクライアント遷移で判定されることを確認する。起動済みの開発サーバーで配信用の設定が無いときは、理由を示して確認を見送る
  - 完了: 上記の確認がヘッドレスブラウザで通り、恒久的なテスト資産として残る
  - _Boundary: SurveyE2eHarness_
  - _Depends: 3.1, 3.2_

- [ ] 4.2 ダイアログの操作と送信・辞退の経路を、ヘッドレスブラウザで操作後の表示として確認する
  - 未選択の間は送信できず、すべて選ぶと送信できること。背景のクリックと Esc で閉じないこと、上限を超えて選べないこと、小さな画面で最後の質問と送信の操作に到達できること、取り消せない旨が読めることを確認する
  - 送信の重複・終了・未認証では静かに閉じて期待どおりに記録され、それ以外の失敗では文言を示して選択が保たれ再送信できることを確認する
  - 「回答しない」を選ぶと操作が「閉じる」になり、送信されず閉じ、同じタブの再読み込みで出ず通信もなく、新しいコンテキストでは再び確認されて出ること。複数選択で「回答しない」と他が同時に選ばれないことを確認する
  - 英語の表示言語で固定の文言と設定の英語の文言が出ること、言語の切り替えで選択が保たれることを確認する
  - 完了: 上記の確認がヘッドレスブラウザで通り、恒久的なテスト資産として残る
