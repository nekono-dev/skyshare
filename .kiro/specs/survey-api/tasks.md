# Implementation Plan

- [ ] 1. 基盤: データ構造・データベース呼び出しの拡張・共通のエラー応答
- [x] 1.1 (P) 回答済みの集合と匿名の回答の 2 つのテーブルを、移行として用意する
  - 回答済みの集合は、アンケートと回答者の値の組を一意にし、回答への参照も時刻も持たない
  - 匿名の回答は、アンケートと乱数の識別子の組を一意にし、回答の内容と回答した日だけを持ち、回答者に関わる値を持たない
  - どちらも挿入順を持たない形にし、2 つのテーブルの間に共通の値や参照を作らない
  - 完了: 既存の移行をすべて適用した状態で 2 つのテーブルが作られ、列・一意性・挿入順を持たないことをテストで確認できる
  - _Boundary: SurveyTables_
  - _Requirements: 6.2, 6.3, 6.5, 10.7_
- [x] 1.2 (P) 複数の文を 1 回で原子的に実行する呼び出しを、データベースの型とテスト用のデータベースに加える
  - 型に、複数の文をまとめて実行し、どれかが失敗したら全体を取り消す呼び出しを足す
  - テスト用のデータベースは、同じ振る舞いをトランザクションで再現し、まとめた実行を 1 回の呼び出しとして数える
  - 既存の予約投稿のテストが変わらず通る
  - 完了: まとめた実行が成功すると全文が反映され、途中で失敗すると何も残らず、呼び出し回数が 1 と数えられることをテストで確認できる
  - _Boundary: SurveyStore_
  - _Requirements: 6.7, 9.3_
- [x] 1.3 (P) 共通のエラー応答に、処理できない内容（422）を加える
  - 状態コード 422 を、言語を持たない分類のエラーとして、キャッシュさせない指定つきで返せるようにする
  - 既存の状態コードの応答は変えない
  - 完了: 422 を指定すると、内容のない分類のエラーとキャッシュ禁止の指定を持つ応答が返り、既存の状態コードの応答が変わらないことを単体テストで確認できる
  - _Boundary: SurveyRequestGate_
  - _Requirements: 1.3, 5.7_

- [ ] 2. コア: 契約・検証・匿名化・保管・削除・入口・鍵の用意
- [ ] 2.1 (P) 3 つの操作の API 契約を、コードファーストのスキーマとして定める
  - 回答済みの確認（結果は回答済みかの真偽だけ）、回答済みとしての登録（本文なし、内容のない成功）、回答の保存（質問ごとの選択結果。定義にない項目は拒否。内容のない成功）の入力・出力・状態コードを定める
  - アンケートの識別子は設定と同じ形式で検証し、入力に回答者の識別子や時刻を持たせない
  - 質問や選択肢の件数に上限を置く
  - 3 つの操作を API の一覧に登録し、共通のエラー応答の説明表に 422 を足す。生成されるクライアントが更新される
  - 完了: 不正な識別子・定義にない項目・回答者の識別子を含む本文が拒否され、妥当な入力が通ることを単体テストで確認でき、クライアントの生成と型検査が通る
  - _Boundary: SurveyApiSchema_
  - _Requirements: 1.2, 1.4, 3.1, 3.4, 4.3, 5.1, 5.8_
- [ ] 2.2 (P) 回答を設定と照合して検証し、保存用に整える処理を作る
  - 全質問の選択が揃うこと、無い質問や無い選択肢が無いこと、単一選択は 1 つ、複数選択は 1 つ以上で重複がなく上限以下であることを検証する
  - 構造が妥当なうえで「回答しない」の選択肢を含む回答は、未完了として区別して返す。構造の不正と重なるときは不正を優先する
  - 保存用に、質問の順と選択肢の順へ並べ替え、選択の順番を残さない
  - 回答した日を日本標準時の暦で、日より細かい時刻を含めずに求める
  - 完了: 各種の不正・未完了・妥当な回答と、日付の境界（日本時間の日付が変わる時刻の前後）の単体テストが通る
  - _Boundary: AnswerValidation_
  - _Requirements: 5.2, 5.3, 5.4, 5.5, 5.6, 5.7, 6.3_
- [x] 2.3 (P) 回答者の一方向の値を求める処理を作る
  - アンケートの識別子と回答者の識別子から、秘密の鍵を使って固定長の値を求める
  - 同じアンケートで同じ回答者は常に同じ値、別の回答者・別のアンケート・別の鍵では別の値になる
  - 鍵が不正なときは、値を含まない固定の失敗にする。鍵・回答者の識別子・値をログに出さない
  - 完了: 既知の入力に対する出力の固定、各種の入力違いで値が変わること、不正な鍵で値を含まない失敗になることの単体テストが通る
  - _Boundary: RespondentHash_
  - _Requirements: 6.4, 6.6, 7.4, 9.4_
- [x] 2.4 (P) 2 つのテーブルの読み書きと削除を行う保管の処理を作る
  - 回答済みの確認を主キーでの読み取り 1 回、回答済みとしての登録を重複を無視する書き込み 1 回で行う
  - 回答の保存を、回答済みの集合への通常の挿入と回答の挿入を 1 回の原子的な呼び出しにまとめて行い、事前の読み取りをしない。集合の一意性の違反だけを重複として区別して返し、ほかの失敗はそのまま投げる
  - アンケートごとに、回答済みの集合と回答を別々に削除でき、削除した行数を返す
  - 引数にも戻り値にも回答者の識別子を現さない
  - 完了: 確認・登録の呼び出し回数、保存が両方のテーブルに入ること、2 回目が重複になり回答が増えないこと、登録だけ済ませたあとの保存が重複になること、失敗時に何も残らないこと、削除が対象のアンケートだけを消し削除済みで 0 を返すことを、テスト用のデータベースで確認できる
  - _Boundary: SurveyStore_
  - _Depends: 1.1, 1.2_
  - _Requirements: 3.2, 3.3, 3.5, 4.1, 4.2, 4.4, 6.1, 6.7, 7.1, 7.2, 7.3, 7.5, 8.1, 8.2, 8.7, 9.3_
- [ ] 2.5 (P) 回答者の値を求める秘密の鍵を、配備とローカルの準備の自動登録に載せる
  - 未登録のときだけランダムな値を生成し、登録済みの値は上書きしない。予約投稿の暗号鍵とは別のキーと値にする
  - develop とそのプレビューの両方に同じ値を登録する。片方にだけ登録済みのときは、作り直さずに手動の対処が必要なことを示して失敗で終える
  - ローカルの設定の雛形に、鍵の説明を足す
  - 手元の準備と配備の手順の説明に、新しい鍵を反映する
  - 完了: 登録の計画に新しい鍵が現れ、登録済みが上書きされず、片方だけのときに失敗すること、ローカルの生成が未設定の鍵だけを埋めることを、既存の同種のテストへの追加で確認できる
  - _Boundary: HashKeyProvisioning_
  - _Requirements: 10.1, 10.2, 10.3, 10.4, 10.5, 10.6_
- [ ] 2.6 3 つの操作の共通の入口を作る
  - 認証、アンケートの識別子の形式、設定の取得と現在のアンケートとの一致、鍵の有無の順に判定し、どの失敗でもデータベースに触れない
  - 回答者の識別子はログインの状態からだけ得る。設定が無い・取得できない・期間外・未定義は、同じ「見つからない」にする
  - 通った場合は、アンケート・回答者の識別子・データベース・鍵・現在時刻を渡す。応答にはキャッシュ禁止の指定を付ける
  - Bluesky 連携の重いライブラリを読み込まない
  - 完了: 未認証・不正な識別子・未定義・期間外・設定なし・鍵なしがそれぞれ想定の状態コードになり、データベースが呼ばれないこと、判定の順序が固定されていること、期間内で通ることを単体テストで確認できる
  - _Boundary: SurveyRequestGate_
  - _Depends: 1.3, 2.1_
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 2.1, 2.2, 2.3, 2.4, 2.5, 9.1, 9.2, 9.4_
- [ ] 2.7 保持期限を過ぎたデータを削除する処理を作る
  - 設定を静的な配信物から読み、アンケートごとに保持期限を過ぎたかを判定する。回答済みの集合は終了時刻以後、回答は終了の 1 か月後以後に削除する。開催中や未開催のものは削除しない
  - 設定が無いときは、データベースに触れずに終える
  - 項目ごとに失敗を記録して次へ進み、全体も例外を外へ投げない。状態を持たず、繰り返しても結果が変わらない
  - 完了: 時刻を動かして、終了前は削除されず、終了後に集合だけ、1 か月後に回答も削除されること、設定なしでデータベースが呼ばれないこと、1 件の失敗が次を止めないこと、繰り返しても変わらないことの単体テストが通る
  - _Boundary: SurveyRetention_
  - _Depends: 2.4_
  - _Requirements: 8.1, 8.2, 8.4, 8.5, 8.6, 8.7, 8.8_

- [ ] 3. 統合: ルートと定期実行への組み込み
- [ ] 3.1 回答済みの確認と登録のルートを組み込む
  - 確認は入口を通ったあと回答者の値を求めて読み取り 1 回で結果を返し、登録は書き込み 1 回で内容のない成功を返す。本文は読まない
  - 予期しない失敗は、内部の情報を含まない失敗として返し、応答はすべてキャッシュを禁止する
  - 完了: 未回答の確認が偽、登録後の確認が真、登録の繰り返しが同じ成功、別のアカウントは別の結果、未認証・期間外が拒否されることを、ルートのテストで確認でき、確認と登録がデータベースに行う呼び出しが 1 回ずつである
  - _Boundary: RespondentRoute_
  - _Depends: 2.1, 2.3, 2.4, 2.6_
  - _Requirements: 1.3, 1.5, 3.1, 3.2, 3.3, 4.1, 4.3, 9.1_
- [ ] 3.2 回答の保存のルートを組み込む
  - 入口を通ったあと本文の形式（不正は拒否）、設定との照合（構造の不正は拒否、「回答しない」を含む回答は未完了として拒否）を行い、回答者の値を求めて 1 回の保存を行う。重複は競合として拒否し、成功は内容のない作成の成功にする
  - 回答の識別子は乱数、回答した日は日本標準時の暦にする
  - 失敗の記録に、回答者の識別子・値・回答の内容・鍵を含めない
  - 完了: 保存の成功、同じアカウントの 2 回目の競合、登録だけ済ませたアカウントの競合、別のアカウントの成功、同時の 2 回の要求で 1 件だけが保存されること、「回答しない」を含む回答が未完了で何も保存されないこと、構造の不正が拒否されること、保存された 2 つのテーブルの行から回答者の識別子が見つからないこと、事前の読み取りが無いことを、ルートのテストで確認できる
  - _Boundary: AnswersRoute_
  - _Depends: 2.1, 2.2, 2.3, 2.4, 2.6_
  - _Requirements: 1.3, 1.5, 5.7, 6.1, 6.2, 6.5, 7.1, 7.2, 7.3, 7.4, 7.5, 9.1_

  - 毎分の予約の実行には何も足さない
  - 完了: 日次の枠の分だけ削除が呼ばれ、ほかの分では呼ばれないこと、削除が失敗しても予約投稿の後片付けが実行されることを、定期実行のテストで確認できる
