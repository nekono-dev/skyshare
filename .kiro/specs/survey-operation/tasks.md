# Implementation Plan

- [ ] 1. 基盤: 検証用の資材
- [x] 1.1 下書き・既存の設定・外部コマンドの固定の出力例を用意する
  - 有効な下書き（識別子あり・なし）、不正な下書き（言語の欠落・期間の重複・未定義の項目）、既存の設定（複数のアンケート、期限切れを含む）を、テストの資材として置く
  - 変数が未設定のときと認証切れのときの出力例、回答データの確認の出力例（行あり・行なし・進捗の行が混ざった出力・失敗）を置く
  - 資材はアプリのソースコードの外に置き、秘密情報や実在の回答を含めない
  - 完了: 有効な資材が上流の検証を通り、不正な資材が 1 件ずつ拒否されることを確かめる単体テストが通る
  - _Boundary: SurveyRemote, SurveyConfigEditor, SurveyLifecycle_
  - _Requirements: 3.5, 5.4, 8.1_

- [ ] 2. コア: 規則と外部呼び出し
- [x] 2.1 (P) アンケートの追加・除去の変換と正規化を作る
  - 下書きを既存の設定に加えた全体を上流の検証にかけ、不正なら位置と理由だけを返す（入力の値を含めない）
  - 識別子を決める。指定があればそれを使って同じ識別子のアンケートを置き換え、無ければ同じ内容の既存の識別子を再利用し、それも無ければ開始の年月（日本標準時）と連番から衝突しない識別子を作る
  - アンケートを開始時刻順に並べ、スキーマの順の値にして、入力の順序に依らず同じ値を作る。既存の他のアンケートの内容は変えない
  - 容量の上限（48KB）を超える値と、既存と同じ内容（変更なし）を区別して返す
  - アンケートを識別子の指定で取り除く変換を持つ
  - 完了: 新規・同じ内容・同じ年月の 2 件目・識別子の明示・不正・容量超過・順序違いの入力が、それぞれ期待どおりの結果になる単体テストが通り、不正の報告に入力の値が含まれない
  - _Boundary: SurveyConfigEditor_
  - _Requirements: 1.4, 2.5, 3.1, 3.2, 3.3, 3.4, 3.5, 3.6, 3.7, 3.9, 4.2, 5.1, 7.4_
- [x] 2.2 (P) アンケートの段階の判定と、除去の候補・判定を作る
  - 時刻から、開始前・実施中・終了後で回答の保持中・保持期限切れのいずれかを判定する。保持期限の判定は上流のものを使い、独自に日付を計算しない
  - 除去の候補を保持期限切れのアンケートだけにする
  - 候補ごとに、すべてのデータベースで行が無いときだけ除く。行がある、または確認できなかったものは残し、理由を区別して返す
  - 完了: 保持期限の直前は候補にならず期限ちょうどで候補になること、本番だけ行なし・開発に行あり・確認不能のそれぞれで除かれず、すべて行なしのときだけ除かれることを、時刻を動かす単体テストで確認する。同じ入力で結果が変わらない
  - _Boundary: SurveyLifecycle_
  - _Requirements: 4.1, 5.1, 5.2, 5.3, 5.4, 5.5, 5.9, 5.10_
- [x] 2.3 (P) 設定の元と回答データへの外部呼び出しを作る
  - 設定の元の取得（未設定は「なし」）・設定・削除を、手元で認証済みの道具で行う。値は標準入力で渡し、引数・出力・例外に残さない
  - 保持期限切れのアンケートについて、本番と開発の両方のデータベースの 2 表の行の有無を、読み取りだけの問い合わせで 1 回ずつ確かめる。確かめられなかったときは例外にせず「不明」とする
  - 失敗を認証・利用不可・解析不能の固定の分類にし、外部コマンドのエラー文を返さない。識別子が規則に合わないときは問い合わせない
  - 認証情報は環境変数を優先し、無ければ配備用の設定ファイルの値を使う
  - 完了: 固定の出力例で、未設定と認証切れの判別、進捗の行が混ざった出力の解析、失敗時に「不明」になること、書き込み・削除の文が発行されないこと、値や認証情報が出力に現れないことを確認する単体テストが通る
  - _Boundary: SurveyRemote_
  - _Requirements: 3.8, 5.4, 5.5, 5.6, 5.8, 7.1, 7.2, 7.3_

- [ ] 3. 統合: 道具・手順・定型工程
- [ ] 3.1 追加・状態・除去のコマンドを作り、1 つの流れに束ねる
  - 追加は下書きのファイルを受け、読む→変換→正規化→比較→書くの流れで、変更が無ければ書かない。実行せずに要約だけ示す指定を持つ
  - 状態は、各アンケートの段階と使用量を示し、書き換えず回答データにも触れない
  - 除去は、候補が無ければ回答データに問い合わせず、除く対象があれば書き換え、残りが 0 件になるときは設定の元を未設定にする。繰り返しても結果が変わらない
  - 成功は 1 行の要約、失敗は理由 1 行と異常終了。要約に設定の本文・回答・認証情報を含めない。除去は失敗しても確認できなかったことが分かる出力にする
  - 実行用のスクリプトを登録し、配備用の設定ファイルの雛形に、設定の元はこの道具が管理するため書かない旨を示す
  - 完了: 偽の外部呼び出しを使う統合テストで、追加の新規・更新・変更なしの書き込み回数、実行せずの指定で書き込みが 0 回、未設定からの追加、除去の各ケース（候補なし・行あり・不明・全件除去・再実行）、出力が 1 行であること、状態が書き込みと問い合わせをしないことが確認できる
  - _Boundary: SurveyCli_
  - _Depends: 2.1, 2.2, 2.3_
  - _Requirements: 1.5, 3.1, 3.2, 3.4, 3.8, 4.1, 4.2, 4.3, 4.4, 5.7, 5.8, 5.9, 5.10, 6.3, 7.2, 7.3, 8.1, 8.2, 8.3, 8.4_
- [ ] 3.2 聞き取り・翻訳・確認・登録の手順をプロジェクトスキルとして作る
  - アンケートを実施したい旨の依頼で起動し、期間・タイトル・説明・質問・選択肢・複数選択の上限・「回答しない」の有無を 1 回の依頼でまとめて尋ねる。日本語のみを受け、不足分だけ再度尋ね、自由記述は受けない
  - 日本語以外のすべての対応言語（言語の一覧から読む）の翻訳を作り、日本語と各言語の文言・期間・上限・「回答しない」の有無を 1 つの表にして示し、確認を求める。修正は反映して示し直し、確認までは設定の元を書き換えない
  - 既存の修正は、状態の確認で対象を特定し、識別子を指定して同じ流れで更新する。設定の本文には内容だけを載せ、下書きは作業用の一時ファイルに書いて登録後に消す
  - 手動での除去の手順と結果の読み方、設定の元を直接書き換えないこと、アンケートを設定から手で消さないことを手順に含める
  - 完了: スキルが Git の管理対象になる場所に置かれ、起動の語・聞き取り項目・翻訳・確認・登録・修正・除去の各手順を含む
  - _Boundary: SurveyRunSkill_
  - _Depends: 3.1_
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 1.5, 2.1, 2.2, 2.3, 2.4, 2.5, 7.4_
- [ ] 3.3 main へ取り込む前の除去を、プロジェクトの作業手順の定型工程にする
  - 開発用ブランチから本番用ブランチへ取り込む（取り込みの依頼を受ける）とき、取り込みの前に除去を実行して 1 行の結果を報告する規則を、作業手順の正本に足す。運営者の追加の指示を待たない
  - 取り込みより前に行う理由（本番の配備が実行時に設定の元を読む）と、失敗・確認不能のときは報告して設定の元を変えないまま取り込みを続けられることを書く
  - 認証は手元のものを使い、CI に書き込みの権限を預けないことを書き、実行方法の詳細はスキルを参照する
  - 完了: 作業手順の正本に、取り込み前に除去を行う節があり、スキルへの参照を含む
  - _Boundary: ReleaseWorkflowRule_
  - _Depends: 3.2_
  - _Requirements: 6.1, 6.2, 6.3, 6.4, 6.5_
