# コーディング規約

## 言語

- 会話・技術説明・エラーメッセージの解説・README などのドキュメントは日本語で書く
- コード内のコメントは日本語を基本とし、同一責務の説明で日英を混在させない

## React コンポーネント

- 必ずアロー関数で書き、デフォルトエクスポートも行う
  ```ts
  export const Component = () => {
    return ...
  }
  export default Component
  ```
- 原則 SSG（Static Site Generation）での利用を想定する

## CSS

- CSS モジュールのクラスは `${xx.yy}` ではなく `${xx["yyy"]}` で参照する
- 共通 UI スタイル（`src/styles/ui.module.css` とその `@import` 先）は `@layer ui` に入れる。共通 UI の CSS ファイルを足すときは `ui.module.css` で `@import "./xxx.css" layer(ui);` とする
- 各コンポーネントの `index.module.css` は**レイヤー外**に書く（レイヤー外は常にレイヤー内より優先されるため、`ui["base-card"]` などと固有クラスを併用して padding などを上書きしても、本番ビルドの CSS 出力順に左右されない）。コンポーネント側で `@layer` を宣言しない
- 例外: 共通 UI のクラスに上書きされる前提の既定値を持つ `Overlay` のように、`ui["width-*"]` などを `className` で受け取るコンポーネントは、既定値を `@layer ui { :where(.xxx) { ... } }` の形で `ui` レイヤー内に詳細度 0 で書く。レイヤー外に書くと ui 側が負ける。別レイヤーを作って `@layer a, b;` で順序を宣言する方式は、バンドラが宣言を分割して順序が崩れるため使わない
- 共通 UI 側で「`className` で渡される利用側のクラスを上書きする」ことを前提にしたルール（例: 可変幅プルダウンの `width: 0; min-width: 100%`）は、レイヤー外の利用側に負けるため `ui` に置かず、受け側コンポーネントの CSS に置く（`.trigger.trigger-auto` のようにクラスを重ねて詳細度を上げる）

## コールバック

`map(fn)`・`filter(fn)`・`some(fn)`・`find(fn)`・`reduce(fn)` のように、組み込みメソッドから複数の引数が暗黙的に渡されるコールバックは、関数参照を直接渡さない。アロー関数で、呼び出す関数に渡す引数を明示する。

- 悪い例: `items.map(toShareFile)`
- 良い例: `items.map((item, index) => toShareFile(item, index))`

## コードの説明（コード理解負債の改善規定）

自動生成コード以外に適用する。

- ファイル先頭に、責務と処理概要を書く
- 関数・メソッドごとに、目的・Input・Output・例を書く。最小テンプレート:
  ```ts
  /**
   * 機能の要約（1-2行）
   *
   * 想定する入力形状(必要な場合): / 処理の趣旨: （必要な場合）
   *
   * Input:
   * - `arg`: 説明
   *
   * Output:
   * - 戻り値の説明
   *
   * 例:
   * - 入力: ... / 出力: ...
   */
  ```
- `unknown` や外部入力を扱う処理では、期待する入力形状（最小要件）を書く
- 分岐やループが複雑なブロック（目安: ネスト2段以上、または条件分岐3つ以上）には、何を検証・除外・抽出しているかの意図を書く
- 推奨: 失敗時の方針（`undefined` を返す、早期 return など）、副作用の理由（状態更新・外部 I/O・リソース解放）、実装上の制約（Workers 制約・API 互換性）を書く
- 禁止: コードを見れば自明なコメント（代入・単純なインクリメントの説明）と、実装と乖離した古いコメントの放置
