# 通知の発行 アーキテクチャ

## 1. 目的と範囲

通知の発行は、発行元システムの要求を検証して通知を受け付ける。
通知の保管と表示は、別の機能のくくりの対象である。

## 2. 構成要素

| 構成要素       | 種別   | 責務                                               | 実装spec           |
| -------------- | ------ | -------------------------------------------------- | ------------------ |
| 発行元システム | 外部   | 通知の内容と宛先を送り、受理か拒否の応答を受け取る | -                  |
| 発行API        | 内部   | 要求の API キーと宛先を確認して受け付ける          | publish-api        |
| 宛先管理       | 内部   | 宛先の有効と無効を保持して照会に答える             | recipient-registry |
| 配信ワーカー   | 他機能 | 受け付けた通知を宛先ごとに保管する                 | -                  |

## 3. システム構成

通知の受け付けは、宛先の確認と保管の依頼に分かれる。

```mermaid
flowchart LR
  api["発行API"] --> registry["宛先管理"]
  api --> worker["配信ワーカー"]
```

## 4. 外部インターフェース

| IF       | 方向 | 外部の要素     | 内部の要素 | 方式          | 認証     |
| -------- | ---- | -------------- | ---------- | ------------- | -------- |
| 通知発行 | 提供 | 発行元システム | 発行API    | HTTPS（JSON） | API キー |

発行元システムは、通知発行の辺で発行APIにつながる。

```mermaid
flowchart LR
  subgraph システム境界
    api["発行API"]
  end
  ext_source["発行元システム"] -->|通知発行| api
```

## 5. 機能

### 通知の受付

- 関与: 発行元システム、発行API、宛先管理

通知の受付は、宛先が無効な場合に拒否する分岐を持つ。

```mermaid
sequenceDiagram
  participant ext_source as 発行元システム
  participant api as 発行API
  participant registry as 宛先管理
  ext_source->>api: 通知の発行
  api->>registry: 宛先の照会
  alt 宛先が有効
    api-->>ext_source: 受理
  else 宛先が無効
    api-->>ext_source: 拒否
  end
```
