# 通知の保管 アーキテクチャ

## 1. 目的と範囲

通知の保管は、受け付けた通知を宛先ごとに振り分けて保管し、既読位置を管理する。
通知の受け付けと画面への表示は、別の機能のくくりの対象である。

## 2. 構成要素

| 構成要素     | 種別 | 責務                                         | 実装spec           |
| ------------ | ---- | -------------------------------------------- | ------------------ |
| 配信ワーカー | 内部 | 通知を宛先ごとに振り分けて保管する           | delivery-worker    |
| 通知ストア   | 内部 | 通知と既読位置をデータベースに書き込んで返す | notification-store |
| 既読管理     | 内部 | 宛先ごとの既読位置を初期化して更新する       | read-position      |

## 3. システム構成

通知の保管は、書き込みと既読位置の記録に分かれる。

```mermaid
flowchart LR
  worker["配信ワーカー"] --> store["通知ストア"]
  worker --> read["既読管理"]
  read --> store
```

## 5. 機能

### 通知の保管と既読の初期化

- 関与: 配信ワーカー、通知ストア、既読管理

通知の保管は、書き込みの成否で既読位置の初期化に進むかが分岐する。

```mermaid
sequenceDiagram
  participant worker as 配信ワーカー
  participant store as 通知ストア
  participant read as 既読管理
  worker->>store: 通知の書き込み
  alt 書き込みに成功
    store-->>worker: 保管の完了
    worker->>read: 既読位置の初期化
  else 書き込みに失敗
    store-->>worker: 失敗の通知
  end
```

## 6. データ

| データ   | 保管場所                 | 書き込み主体 |
| -------- | ------------------------ | ------------ |
| 通知     | 通知ストアのデータベース | 配信ワーカー |
| 既読位置 | 通知ストアのデータベース | 既読管理     |
