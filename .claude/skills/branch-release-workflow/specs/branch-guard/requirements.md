# ブランチ運用の強制 要件定義書

## 1. 目的

本番向けブランチでの直接作業を防ぎ、作業ブランチで作業させる。運用の正本はリポジトリ内の宣言ファイルとし、判定は文章ではなく Claude Code のフックが機械的に行う。スキル自身は利用開始時に最新へ更新し、古い判定規則で作業しないようにする。

## 2. スコープ

### 2.1 対象

- 宣言ファイルの読み込みと検証。
- commit と push の前に行うブランチの判定。
- 作業ブランチの命名規則の検証と作成。
- スキル利用開始時の自己更新。

### 2.2 対象外

- ブランチの作成を止める判定。
- Bash の git コマンド以外の経路で行う操作の判定。

## 3. 前提

- なし

## 4. 機能要件

- FR-1: 宣言ファイルから作業ブランチ・保護ブランチ・分岐元・命名規則を読み込み、不正な値を検出する。
- FR-2: 保護ブランチ、または宣言にないブランチでの commit と push を拒否する。
- FR-3: 宣言ファイルがない、宣言が不正、ブランチを特定できない、または全ブランチの push を指定したとき、利用者へ確認する。
- FR-4: push の送り先を指定する引数から実際に更新されるブランチを求めて判定する。
- FR-5: 命名規則に合う作業ブランチだけを作成し、規則に合わない名前を拒否する。
- FR-6: スキル利用開始時に git pull の早送りだけで自身を更新し、失敗しても作業を続けられる結果を返す。

## 5. 非機能要件

- NFR-1: フックの判定は、1回あたり 1 秒以内に終える。
- NFR-2: スクリプトが依存する外部パッケージは 0 件にする。

## 6. 受け入れ条件

- AC-1 (FR-1): 作業ブランチの一覧が空の宣言を読み込むと、不正として報告される。
- AC-2 (FR-2): 保護ブランチ上で commit を判定すると、拒否される。
- AC-3 (FR-3): 宣言ファイルのないリポジトリで commit を判定すると、確認が返る。
- AC-4 (FR-4): 作業ブランチから保護ブランチへ送る push を判定すると、拒否される。
- AC-5 (FR-5): 命名規則に合わない名前でブランチの作成を指示すると、作成されずに終了コード 1 で終わる。
- AC-6 (FR-6): git の作業ツリーでないスキルの更新を指示すると、更新できない旨と導入方法が返る。
- AC-7 (NFR-1): 一時リポジトリでの判定 16 件が、合計 10 秒以内に完了する。
- AC-8 (NFR-2): スクリプトの import が Node 標準モジュールと相対パスだけである。
