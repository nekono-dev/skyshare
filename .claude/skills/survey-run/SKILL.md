# アンケートの運用

アンケートの聞き取り、翻訳、利用者の確認、登録、状態確認、除去を案内する。操作は `npm run survey` の専用 CLI だけで行い、`SURVEY_CONFIG` の値を直接変更しない。

## 新しいアンケートの聞き取り

アンケートの実施・追加を依頼されたら、依頼に既にある情報は聞き直さず、不足分をまとめて尋ねる。実施期間について尋ねるのは、終了日時（日本標準時、JST）だけで、開始日時は尋ねない。開始は初回登録時に自動設定され、既存アンケートの更新では元の開始日時が保持される。

必要な情報:

- 質問ごとの題、単一選択または複数選択の形式、選択肢
- 複数選択の選択数上限
- 「回答しない」の選択肢を含めるか
- 締切日（`YYYY-MM-DD`）

アンケート全体の題と説明はない。聞き取る文言は質問の題と選択肢だけにする。入力文は日本語のみ受け付ける。自由記述の質問は扱わず、選択式の質問だけを作る。選択肢 ID は英小文字・数字・ハイフンを使い、質問内で重複させない。締切日は実在する日付として受け取り、`YYYY-MM-DD` のまま下書きに記す。この日付は日本時間 0 時を表す。

## 既存アンケートの更新

更新依頼では、最初に `npm run survey -- status --env production` と `npm run survey -- status --env develop` を実行する。結果にある ID と段階を示し、更新する ID を確認する。対象 ID を特定してから不足項目を聞き取り、下書きのトップレベルに対象の `id` を入れる。更新はその ID の設定だけを対象にする。対象を特定できるまでは下書きを作らず、更新コマンドも実行しない。

開催中の更新は締切の前倒しだけを受け付ける。指定する締切日は現在の締切より前で、開始日時より後にする。集計済みの ID の締切変更と終了済みアンケートの再開はできない。前倒しできる日付がない場合は `error: refused: 前倒しできません。自然な終了と集計を待ってください。` が返るため、自然な終了と集計を待つ。

## 翻訳と登録前の確認

1. `src/lib/i18n/locale.ts` の `LOCALES` を読み、日本語以外のすべての言語に質問の題と選択肢を翻訳する。対応言語を固定リストとして扱わない。
2. 日本語とすべての翻訳を、質問ごとに分けた一つの確認表にまとめる。表には質問の題、選択肢、単一／複数の形式、複数選択の上限、「回答しない」の有無を含める。
3. 表には新規登録時に開始日時が自動設定され、更新では既存の開始日時が保持されること、締切日（`YYYY-MM-DD`、日本時間 0 時）を明記する。利用者が上限・辞退の有無も確認できる形にする。
4. 利用者に内容の明示的な確認を求める。確認前に `add` を呼ばず、下書きファイルも作らない。修正依頼があれば翻訳を含む表全体を更新して再提示し、改めて明示的な確認を待つ。
5. 明示的な確認を受けた後に限り、確認済みの内容で JSON 下書きを作る。形式は `tests/fixtures/survey-operation/without-id.json` を参照する。新規登録では `id` と `opensAt` を省略する。識別子は CLI が UUID v4 を自動発行するため、手で入力しない。更新では対象 `id` を含め、`opensAt` は指定しない。質問・選択肢は各 `LOCALES` の文言を含める。
6. 下書きはリポジトリ外の一時 JSON ファイルに作成し、パスを安全に引用する。`npm run survey -- add --file <一時ファイル>` で登録または更新する。実行後は成功・失敗のどちらでも一時ファイルを削除する。
7. 新しい登録は、設定にあるすべての ID が本番・develop 両方の目録に記録されるまでできない。開始前のアンケートも登録を止める。設定に残る集計済みの過去分は登録を止めない。目録の取得に失敗した場合は原因を解消してから再実行する。
8. 確認だけを行う場合は `npm run survey -- add --file <一時ファイル> --dry-run` を使う。dry-run も明示確認後に作った一時ファイルに対して行い、処理後に削除する。

## 状態確認

状態確認依頼では本番・develop の両方について `npm run survey -- status --env <環境>` を実行する。出力は設定とその環境の目録を合わせた表全体で、設定だけの行・目録だけの行も含む。`status は表全体、それ以外は固定の 1 行だけ` を報告する。空なら `status: env=<環境> no surveys` と表示される。

各行の段階（`closes` の時刻は日本時間）の意味は次のとおり。

- `upcoming`: 開始前。
- `active`: 開催中。
- `closed`: 終了済みで、その環境ではまだ集計されていない。
- `empty`: 集計したが、有効な回答が無かった（結果は作られず、公表もできない）。
- `hidden`: 集計済みで結果があり、非公開。
- `published`: 集計済みで結果があり、公開中。

行の末尾の `!invalid-visibility` は、公開の可否を表すファイルの形式が不正だという警告で、段階は `hidden` として扱う。行の最後の `config` は設定にあるアンケート、`r2-only` は設定から除去済みで集計の記録だけが残るアンケートを示す。終了前のアンケートは、集計の記録があっても時刻の段階（`upcoming`・`active`）を優先して表示する。

新規登録が次の固定文で拒否された場合、記録がない環境には現在の設定を配備し、日次集計を待つ。`error: refused: 未集計のアンケートがあります。集計を待つか、開始前なら remove、開催中なら締切を前倒しして両環境へ配備し、集計を待ってください。`

```sh
npm run survey -- status --env production
npm run survey -- status --env develop
```

目録の取得失敗は、認証・接続・目録形式を直してから同じコマンドを再実行する。

## 公開・非公開の切り替え

集計済みで結果があるアンケートは、`npm run survey -- publish <ID> --env <環境>` で公開し、`npm run survey -- unpublish <ID> --env <環境>` で非公開にする。画面への反映には再配備が必要で、CLI は切り替え後に再配備を起動する。`--no-deploy` は再配備を起動せず、`--dry-run` は書き換えも起動もしない。対象環境には `production` または `develop` を指定する。

CLI が示すのは再配備の起動までで、配備の完了や画面への反映は確認しない。運用者が GitHub Actions で完了を確認する。

## 設定からの除去

個別の除去には `remove <ID>`、終了済みアンケートの一括除去には `prune` を使う。どちらも本番と develop の目録を読み直す。開始前の `remove` は除去できる。開催中は拒否され、終了済みは両方の目録に記録がある場合だけ除去できる。まず dry-run の結果を確認する。

```sh
survey_id='対象のID'   # `status` で確認した ID を書く
npm run survey -- remove "$survey_id" --dry-run
npm run survey -- prune --dry-run
```

対象を確認してから実際に除去する。除去後にアンケートが残らない場合、設定変数そのものが削除される。

除去は、終了の翌日以降（日次の枠が 1 回以上動いた後）に行う。除去の前に、Worker の日次の記録（Cloudflare のログ）に、アンケートの回答の削除の失敗が出ていないことを確かめる。これは削除の失敗に早く気づくための補助で、除去の安全性の前提ではない（設定から外れた終了済みの識別子の残存回答は、翌日以降の日次の枠が片付ける）。

```sh
npm run survey -- remove "$survey_id"
npm run survey -- prune
```

結果の意味:

- `removed <id>`: 設定から除去したアンケート。
- `kept <id>(not-aggregated: <環境>)`: その環境の目録に記録が無く、保持したアンケート。
- `nothing to remove` または `nothing removed`: 除去対象が無い、またはすべて保持した。
- `error: refused: <id> is active`: 開催中のため拒否した。
- `error: refused: <id> is closed ... not aggregated: <環境>`: 終了済みだが、両環境の集計がそろわないため拒否した。

開催中のアンケートを取り下げる場合は、同じ ID で締切を前倒しして更新し、更新した設定を本番と develop の両方へ配備する。設定を更新しただけでは、配備済みの Worker は回答の受付を止めない。日次集計を待ち、両環境で `status --env` を実行して `empty`・`hidden`・`published` のいずれかになったことを確認してから `remove` または `prune` を実行する。除去時にも両方の目録を読み直す。

すでに集計済みのアンケートの終了日時は延ばさない。続ける場合は、新しい ID で登録する。

### 集計されていない環境がある場合

`kept` や `not aggregated` は、その環境の目録に記録が無いことを示す。期間の不一致を示すものではない。現在の設定をその環境へ配備し、日次集計を待ってから除去を再実行する。`develop` の記録が無い場合は、`gh workflow run deploy.yaml --ref develop -f dry_run=false` で `develop` を再配備し、翌日の日次の枠を待つ。

目録の取得そのものに失敗した場合は、認証・接続・応答形式を直して再実行する。失敗時は設定を変更しない。`gh variable set` などで `SURVEY_CONFIG` を直接変更せず、JSON からアンケートを手動削除しない。

## コマンド出力と失敗時の扱い

`status は表全体、それ以外は固定の 1 行だけ` を利用者に伝える。設定本文、回答、認証情報、外部コマンドの標準エラーを調べたり、貼り付けたりしない。新規登録の固定拒否文が出たら、記録がない環境へ現在の設定を配備して日次集計を待つ。目録の取得失敗は認証・接続・形式を直して再実行する。`error: auth` はローカル認証、`error: invalid` は入力・設定・目録形式の確認が必要という意味である。エラー時も一時ファイルを削除する。
