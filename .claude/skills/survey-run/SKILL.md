# アンケートの運用

このスキルは、アンケートの聞き取りから登録・状態確認・期限切れ項目の除去までを進める。設定の元は `SURVEY_CONFIG` であり、専用 CLI だけで操作する。

## 新しいアンケートの聞き取り

依頼文に「アンケートを実施したい」「アンケートを追加したい」が含まれるときに開始する。最初の質問で次の項目をまとめて確認する。依頼に既に含まれる項目は聞き直さず、不足分だけを質問する。

- 実施期間（開始・終了の日付と時刻。日本標準時で尋ねる）
- アンケートのタイトルと、任意の説明
- 各質問の文面と形式（単一選択または複数選択）
- 各質問の選択肢
- 複数選択の場合の選択数の上限
- 「回答しない」の選択肢を含めるか

受け取る原文は日本語に限る。自由記述の質問は受け付けない。選択肢の識別子は英小文字・数字・ハイフンを使い、質問内で重複させない。日付は日本標準時の暦で解釈し、CLI に渡す日時はオフセット付き ISO 8601（例: `2026-11-01T00:00:00+09:00`）にする。終了時刻は終了の瞬間を含まない。

## 翻訳と登録前の確認

1. `src/lib/i18n/locale.ts` の `LOCALES` を読み、日本語以外のすべての対応言語に翻訳する。言語を固定の一覧として扱わない。
2. 次の内容を一つの確認表にまとめて提示する。タイトル・説明・質問・選択肢の日本語と各翻訳、開始・終了時刻、質問形式、複数選択の上限、「回答しない」の有無を含める。

   | 対象 | 日本語 | 各対応言語 | 形式・上限・辞退 |
   | --- | --- | --- | --- |
   | タイトル／説明 | 文面 | 言語ごとの文面 | — |
   | 期間 | 開始・終了（JST） | — | オフセット付き日時 |
   | 質問と選択肢 | 質問・選択肢 | 言語ごとの質問・選択肢 | 単一／複数、上限、辞退の有無 |

   質問が複数ある場合は、質問ごとに表の行を分ける。
3. 利用者に表の内容確認を求める。明示的な確認を得るまでは、下書きを CLI に渡したり、設定の元を書き換えたりしない。修正依頼があれば内容を直し、表全体を示し直して再確認を求める。
4. 確認後に限り、表で確認された内容だけを JSON 下書きにする。必要な形は `tests/fixtures/survey-operation/drafts/without-id.json` を参照する。登録用の下書きにはアンケートの内容だけを含め、回答者情報・秘密情報・個人名は含めない。
5. 下書きはリポジトリ外の一時ファイルに作成する。登録後、成功・失敗にかかわらず一時ファイルを削除する。パスはシェルで安全に引用する。
6. 登録は `npm run survey -- add --file <一時ファイル>` で行う。変更がないかを確認するだけなら `npm run survey -- add --file <一時ファイル> --dry-run` を使う。CLI が返す要約の1行を報告する。

## 既存アンケートの修正

依頼文に「アンケートを修正したい」が含まれるときは、最初に `npm run survey -- status` を実行し、利用者に対象の識別子を確認する。修正対象が特定できてから、同じ聞き取り・翻訳・確認の流れを使う。下書きには対象の `id` を明示し、確認を得るまで登録しない。更新は `npm run survey -- add --file <一時ファイル>` で行い、処理後に一時ファイルを削除する。

## 状態確認

「アンケートの状態を確認したい」という依頼では `npm run survey -- status` を実行し、1行の結果を報告する。結果は各アンケートの識別子と段階（`upcoming`、`active`、`retained`、`expired`）、`SURVEY_CONFIG` の使用量を示す。`status: no surveys` は設定されているアンケートがないことを示す。この操作は設定も回答データも変更しない。

## 期限切れアンケートの除去

通常のリリースでは `.kiro/steering/workflow.md` の取り込み前ルールで自動的に `prune` を実行する。手動で確認する場合は、まず次を実行する。

```sh
npm run survey -- prune --dry-run
```

結果を確認した後に除去を実行する。

```sh
npm run survey -- prune
```

`removed` は除去した識別子、`kept <id>(rows)` は回答または回答済み記録が残るため保持した識別子、`kept <id>(unknown)` は回答データを確認できなかったため保持した識別子を示す。`nothing to remove` は除去候補がないことを示す。確認不能やコマンド失敗では設定の元を書き換えない。

設定の元を `gh variable set` などで直接書き換えない。アンケートを JSON から手で削除しない。回答データの保持期限判定と削除が実行される前に設定から手で除くと、削除対象を特定できなくなるためである。

## CLI の失敗

コマンドが異常終了した場合は、CLI が返した固定の1行だけを報告する。設定本文、回答、認証情報、外部コマンドの標準エラーを調べたり、報告に貼り付けたりしない。`error: auth` はローカルの `gh` または `wrangler` の認証が必要であることを示す。`error: invalid` は入力または既存設定を確認する必要があることを示す。
