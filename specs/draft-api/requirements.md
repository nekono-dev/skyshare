# 下書きAPI 要件定義書

## 1. 目的

1件の投稿とスレッドの下書きを、Blueskyの下書き機能に保存・取得・更新・削除できるようにする。

## 2. スコープ

### 2.1 対象

- 下書きの一覧取得・作成・更新・削除のAPI。
- 下書きの本文と自己ラベルの形式。

### 2.2 対象外

- 画像・動画・リンクカードの下書きへの保存。
- 投稿フォームでの下書きの表示と復元。

## 3. 前提

- なし

## 4. 機能要件

- FR-1: 下書きは1件から100件の投稿の配列とし、1件なら単発投稿、2件以上ならスレッドの下書きとして扱う。
- FR-2: 下書きの各投稿は本文と任意の自己ラベルを持ち、画像・動画・リンクカードは持たない。
- FR-3: 下書きの一覧を、件数の上限と続きを示すカーソルを指定して取得できる。
- FR-4: 下書きを作成すると、その識別子を返す。
- FR-5: 識別子を指定して、下書きの投稿の配列を置き換えられる。
- FR-6: 識別子を指定して、下書きを削除できる。
- FR-7: 連携先から取得した下書きの一覧が想定の形式でない場合は、1件でも不正なら一覧全体を失敗とする。

## 5. 非機能要件

- NFR-1: 下書きの投稿数の上限100件を、投稿の作成と同じ定数から参照する。
- NFR-2: エラー応答を400・401・429・500に分類し、連携先の例外は投稿のAPIと同じ規則で変換する。

## 6. 受け入れ条件

- AC-1 (FR-1): 投稿が0件または101件の下書きの作成は400で拒否され、2件の下書きは作成できる。
- AC-2 (FR-2): 自己ラベルが文字列の配列でない投稿は拒否される。
- AC-3 (FR-3): 件数の上限が範囲外か、カーソルが空文字の一覧取得は400になる。
- AC-4 (FR-4): 下書きを作成すると、200と識別子が返る。
- AC-5 (FR-5): 識別子を指定して2件の投稿に更新すると、200になる。
- AC-6 (FR-6): 識別子を指定して削除すると200になり、識別子が無いと400になる。
- AC-7 (FR-7): 連携先の一覧の応答が不正な形式のとき、500になる。
- AC-8 (NFR-1): 下書きの作成と更新のスキーマが、投稿の作成と同じスレッドの上限の定数を参照する。
- AC-9 (NFR-2): 未認証で401になり、連携先の呼び出しが失敗すると変換したステータスが返る。
