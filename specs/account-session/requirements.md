# アカウントセッション管理 要件定義書

## 1. 目的

Blueskyのログイン状態を端末ごとに安全に保持し、複数アカウントの追加・切り替え・ログアウトと、認証が必要なAPIでのセッションの自動更新を提供する。

## 2. スコープ

### 2.1 対象

- セッションのcookieによる保持と、複数アカウントの非アクティブなセッションのプール。
- セッション一覧の取得、追加ログイン、アカウントの切り替え、ログアウトのAPI。
- v2 の API 配下でのセッションの自動再開とトークンの書き戻し。
- クライアントでのアクティブアカウント情報の共有取得。

### 2.2 対象外

- ログイン失敗時の文言（ログイン入力欄の表示）。
- 旧バックエンドのセッション。
- OAuth のセッションの発行・更新・取消（cookie の形式とプールの規則だけを共有する）。

## 3. 前提

- なし

## 4. 機能要件

- FR-1: セッションは HttpOnly の cookie にのみ保持し、プール中のアカウントは1件ずつ別の cookie に置き、API の応答本文にトークンを含めない。
- FR-2: セッション一覧は、アクティブアカウントを先頭にプール中のアカウントを続けて返し、各アカウントの表示名とアイコンを付与する。
- FR-3: セッション一覧は、cookie が無い、またはアクティブもプールも無い場合に未認証として扱う。
- FR-4: プロフィールの取得に失敗しても、そのアカウントを表示名とアイコンの無い状態で一覧に含める。
- FR-5: 別のアカウントがアクティブな状態でのログインは、現在のアカウントをプールへ退避してから新しいアカウントをアクティブにする。
- FR-6: 同じアカウントでの再ログインは、プールへ退避しない。
- FR-7: プールの保持数が上限（4件）に達している状態での追加ログインは、競合として拒否する。
- FR-8: アカウントの切り替えは、プール中の指定アカウントをアクティブにし、現在のアクティブアカウントをプールへ戻す。
- FR-9: 切り替え対象がプールに無い場合は、見つからないものとして拒否する。
- FR-10: ログアウトは、対象がアクティブアカウントならセッションの cookie を失効させ、プール中のアカウントならプールから除去する。
- FR-11: v2 の API 配下（セッション操作のAPIを除く）は、リクエストごとにセッションを再開し、更新後のトークンを応答の cookie へ書き戻し、再開できないリクエストは未認証として拒否する。
- FR-12: クライアントは、同時に発生したアクティブアカウントの取得を1回のリクエストにまとめ、未ログインと判明した後は同じタブの中で取得を繰り返さない。

## 5. 非機能要件

- NFR-1: セッション操作の4種（一覧・追加ログイン・切り替え・ログアウト）の応答の100%に、キャッシュを禁止する指定を付ける。

## 6. 受け入れ条件

- AC-1 (FR-1): セッションの cookie に HttpOnly が付き、値の復号で元のセッションが得られる。
- AC-2 (FR-2): アクティブとプールの両方があるとき、アクティブアカウントが先頭に並び、プロフィールが付与される。
- AC-3 (FR-3): cookie が無いとき、401 が返る。
- AC-4 (FR-3): cookie はあるがアクティブもプールも無いとき、401 が返る。
- AC-5 (FR-4): プロフィールの取得が失敗しても、200 で空のメタ情報とともに一覧が返る。
- AC-6 (FR-5): 別アカウントがアクティブな状態でログインすると、現在のアカウントがプールへ退避される。
- AC-7 (FR-6): 同じ did で再ログインすると、プールに退避されない。
- AC-8 (FR-7): プールが上限に達しているとき、追加ログインが 409 で拒否される。
- AC-9 (FR-8): 切り替えると、現在のアクティブアカウントがプールへ戻される。
- AC-10 (FR-9): 切り替え対象の did がプールに無いとき、404 が返る。
- AC-11 (FR-10): アクティブアカウントを対象にすると、セッションの cookie が失効する。
- AC-12 (FR-10): プール中のアカウントを対象にすると、プールから除去される。
- AC-13 (FR-11): v2 の API 配下のうちセッション操作のパスを除くパスだけが、自動再開の対象になる。
- AC-14 (FR-11): 再開に成功したリクエストの応答に、更新後のセッションを書き込む Set-Cookie が加わる。
- AC-15 (FR-11): セッションの cookie が無いリクエストは、後続の処理を呼ばずに 401 で拒否される。
- AC-16 (FR-12): 同時に2回取得すると実際のリクエストは1回になり、401 を受けた後は取得がリクエストを送らずに 401 を返す。
- AC-17 (NFR-1): セッション一覧の応答にキャッシュを禁止する指定が付く。
- AC-18 (FR-1): プールの2件がそれぞれ別の cookie に入り、空いた枠の cookie は失効する。
