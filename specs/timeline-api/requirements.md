# タイムラインAPI 要件定義書

## 1. 目的

自分の投稿の一覧を、スレッドの構造を確定させたグループの単位で返し、取得元の一覧に欠けがあっても自分のスレッドを完全な形で表示できるようにする。

## 2. スコープ

### 2.1 対象

- 自分の投稿の一覧の取得とページング。
- スレッドのグループ化と、表示する系統の選出。
- 取得元の一覧から欠けた投稿の補完。
- 投稿に紐づくentryの付与。

### 2.2 対象外

- 一覧の画面での表示。
- entryの作成の可否の判断。

## 3. 前提

- なし

## 4. 機能要件

- FR-1: 自分の投稿を新しい順に返し、リポストと、他人の投稿を起点とするスレッドに属する投稿を返さない。
- FR-2: 自分を起点とするスレッドの、自分の投稿の直線的な連鎖を1つのスレッドグループとして、起点の投稿と古い順の後続の投稿で返す。
- FR-3: 分岐点では直前の投稿との投稿日時の差が最も近い1系統を採用し、候補が1件の分岐点では投稿日時によらず採用する。
- FR-4: 分岐点で採用しなかった系統の投稿は、単独の投稿としても返さない。
- FR-5: 取得元の一覧からスレッドの投稿が欠けていても、起点の投稿を取得できる限り、欠けた投稿を別途取得して補う。
- FR-6: 起点の投稿が取得元の一覧に無い場合は、その起点の投稿の日時に基づく位置に、新しい順を保って挿入する。
- FR-7: スレッドの取得に失敗した場合は、自分が起点の投稿だけを単独の投稿として返し、返信の投稿は返さない。
- FR-8: 系統の選出は一覧の取得のたびにやり直し、採用した系統を保存しない。
- FR-9: 各投稿に、その投稿を派生元とする自分のentryを付与する。

## 5. 非機能要件

- NFR-1: 1ページあたりの取得件数とカーソルによるページングの方式を、グループ化によって変えない。
- NFR-2: スレッドの構造の判定はサーバーの1つの実装だけで行い、クライアントでの返信の連鎖の再構築を0件にする。
- NFR-3: 付与するentryの取得で、表示する投稿のいちばん古い日時の1日前より古いレコードだけのページの取得を0回にする。
- NFR-4: 取得済みの一覧だけでスレッドの構成を確定できる場合は、そのスレッドの個別取得を0回にする。

## 6. 受け入れ条件

- AC-1 (FR-1): リポストが除かれ、自分の投稿だけが返る。
- AC-2 (FR-2): 起点・中間・末尾の3件のスレッドが1つのグループにまとまる。
- AC-3 (FR-3): 分岐したスレッドで、採用した1系統だけが1つのグループになる。
- AC-4 (FR-4): 採用しなかった系統の投稿が一覧に含まれない。
- AC-5 (FR-5): 後続の投稿がすべて欠けていても、中間の投稿が欠けていても、欠けた投稿が補われる。
- AC-6 (FR-6): 起点の投稿が一覧に無いとき、起点の日時に基づく位置に新しい順を保って挿入される。
- AC-7 (FR-7): スレッドの取得に失敗したとき、自分が起点の投稿は単独で返り、返信の投稿は返らない。
- AC-8 (FR-8): 採用した系統の投稿が削除されると、次の取得で別の系統が採用される。
- AC-9 (FR-9): 投稿に紐づくentryが、派生元のURIで突き合わされて付与される。
- AC-10 (NFR-1): 1ページ目が指定件数に満たない場合、カーソルをたどって追加のページを取得する。
- AC-11 (NFR-2): 一覧の応答が、確定済みのスレッドグループの配列の形で返る。
- AC-12 (NFR-3): 表示する投稿より古い日時のentryだけを含むページは取得せず、表示する投稿に紐づくentryは付与される。
- AC-13 (NFR-3): 補完で取得した起点の投稿が一覧より古い場合も、その投稿に紐づくentryが付与される。
- AC-14 (NFR-4): 各投稿の返信数が一覧にある自分の返信の件数と一致するスレッドで、スレッドの個別取得を行わず、取得した場合と同じ系統が選ばれる。
- AC-15 (NFR-4): 返信数が一覧にある自分の返信の件数と一致しないスレッドでは、スレッドを個別に取得して欠けた投稿を補う。
