# 複数画像（5枚以上）添付 要件定義書

## 1. 背景・目的

Bluesky は `app.bsky.embed.gallery` により、1投稿に4枚を超える画像を添付できるようになった（クライアントの運用上限は10枚）。従来の `app.bsky.embed.images` は最大4枚であり、skyshare の投稿フォームも4枚を上限としていた。

本機能は、skyshare から Bluesky へ最大10枚の画像を1投稿に添付できるようにする。あわせて、skyshare entry の visual（代表サムネイル）は枚数に関わらず先頭4枚だけを素材とする方針を定める。

## 2. 用語定義

| 用語           | 意味                                                                                                         |
| -------------- | ------------------------------------------------------------------------------------------------------------ |
| 添付画像       | 1つの投稿（segment）に添付される画像。順序を持つ。                                                           |
| visual         | `dev.nekono.skyshare.defs#manifest` の `visual`。entry の代表画像（サムネイル）。複数画像から1枚に合成する。 |
| visual対象画像 | 添付画像のうち、visual の合成素材となる先頭4枚。                                                             |
| visual対象外   | 添付画像のうち5枚目以降。投稿には含まれるが visual には一切使われない。                                      |

## 3. スコープ

### 3.1 対象

- 投稿フォーム（単発投稿・スレッドの各segment）での最大10枚の画像添付。
- 投稿作成API（`POST /v2/entry`）での最大10枚の画像受け付けと、Bluesky への投稿。
- Bluesky 上の既存投稿（skyshare 以外のクライアントで作成されたものを含む）のうち、5枚以上の画像を持つ投稿の skyshare 内での表示・取り込み。
- visual の素材を先頭4枚に限定する方針（新規投稿時・既存投稿からのentry事後作成時の両方）。

### 3.2 対象外

- 画像以外のメディア（動画等）の複数添付。
- 11枚以上の添付。
- 添付画像の並べ替えUI。
- 下書きへの画像保存（従来どおり下書きは画像を保持しない）。

## 4. 機能要件

### FR-1: 添付枚数の上限

- 1投稿（1segment）に添付できる画像は最大10枚とする。
- 11枚目以降を追加しようとした場合、超過分は追加されず、利用者に上限超過を通知する。
- APIは、11枚以上の画像を含む投稿を400で拒否する。

### FR-2: Bluesky への投稿

- 画像が1〜4枚の投稿は、従来どおり `app.bsky.embed.images` で投稿する（枚数4以下の投稿の互換性を維持するため）。
- 画像が5〜10枚の投稿は、`app.bsky.embed.gallery` で投稿する。
- いずれの場合も、画像の順序・alt（代替テキスト）・縦横比が保持される。

### FR-3: visual の素材

- visual は、添付画像の先頭4枚のみから合成する。5枚目以降は visual の合成に使わない。
- 添付画像が4枚以下の場合の visual は従来どおり。
- 5枚目以降の画像は、投稿には添付されるが、visual の見た目に一切影響しない。
- 先頭画像を削除して繰り上がった画像が先頭4枚に入る場合は、visual にも反映される。
- この方針は、投稿フォームからの entry 作成と、Timeline 上の既存投稿からの entry 事後作成の両方に適用する。

### FR-4: 投稿フォームでの表示

- 投稿フォームのプレビューは、全添付画像を表示し、個別削除・alt編集ができる。
- 5枚目以降の画像には、visual の対象外であることが分かる表示を付ける。
- visual の位置調整（クロップ調整）の対象は先頭4枚のみとする。

### FR-5: 既存投稿の表示

- 5枚以上の画像を持つ Bluesky 投稿（`images` embed・`gallery` embed のいずれか）について、skyshare の各画面は全画像を認識する。
- Timeline のカードに添付画像をそのまま並べる場合（entry未作成時）は、先頭4枚を表示し、5枚目以降は残り枚数（`+N`）で示す。
- entry の詳細ページ・スレッド表示・削除確認ダイアログでは、既存の表示方針に従い、全画像または先頭4枚＋`+N`を表示する（削除確認ダイアログは従来どおり先頭4枚＋`+N`）。

## 5. 非機能要件

- 4枚以下の投稿の挙動（embed型・visual・表示）は変更前と同一であること。
- 各画像の容量上限（gallery・images ともに blob 2,000,000 バイト）を満たす圧縮を、現行と同じ方針で全画像に適用すること。
- Cloudflare Workers 上で動作すること（Node.js固有APIを使わない）。

## 6. 受け入れ条件

- [ ] 投稿フォームで10枚まで画像を追加でき、11枚目は追加されず通知が表示される
- [ ] 5枚の画像を添付して投稿すると、`app.bsky.embed.gallery` の投稿が作成され、画像5枚が順序・altを保って保存される
- [ ] 4枚の画像を添付して投稿すると、従来どおり `app.bsky.embed.images` の投稿が作成される
- [ ] 5枚以上添付してentryを作成した場合、visual は先頭4枚のみから合成され、5枚目以降を変更しても visual は変化しない
- [ ] 投稿フォームのプレビューで、5枚目以降に visual 対象外の表示が出る
- [ ] クロップ調整ダイアログに表示される画像は先頭4枚のみである
- [ ] 先頭の画像を削除すると、繰り上がった5枚目が visual に反映される
- [ ] 5枚以上の画像を持つ既存投稿（images/galleryのどちらでも）から entry を事後作成した場合、visual は先頭4枚から合成される
- [ ] 5枚以上の画像を持つ既存投稿が、Timeline・entry詳細・削除確認ダイアログで全画像を認識した上で、FR-5の方針で表示される
- [ ] APIが11枚以上の画像を含む投稿を400で拒否する
- [ ] 4枚以下の投稿・entryの既存テストがすべて変更なしで通る
