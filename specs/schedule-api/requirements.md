# 予約投稿API 要件定義書

## 1. 目的

利用者が自分の Bluesky アカウントの予約投稿を、作成・一覧・取消できるようにする。投稿時刻に利用者がブラウザを閉じていても投稿できるよう、アプリパスワードで得た予約専用の認証情報を登録させ、その登録と削除も扱う。メインパスワードのサーバー保管は行わない。

## 2. スコープ

### 2.1 対象

- 予約の作成・一覧・取消と、終了した予約の履歴の削除。
- 予約用の認証情報の登録・状態確認・削除。
- 実行時刻の範囲と、アカウントごとの予約件数の検証。

### 2.2 対象外

- 予約の実行と PDS への投稿。
- 予約内容の編集（取消して作り直す）。
- 動画を含む予約。

## 3. 前提

- 前提: schedule-store — 予約と認証情報の保管と取り出しを使う。

## 4. 機能要件

- FR-1: 予約は、1件から100件の投稿・実行時刻・entry の作成指定・投稿ごとの返信と引用の制限・画像を指定して作成できる。
- FR-2: 実行時刻は、現在から5分後以降30日後以内に限り、範囲外は400で拒否する。
- FR-3: 予約用の認証情報が未登録のアカウントによる予約の作成は、409で拒否する。
- FR-4: 予約用の認証情報は、アプリパスワードで新たにログインして得たトークンだけを暗号化して登録し、パスワードを保管しない。
- FR-5: アプリパスワード以外のパスワードで得たセッションは、予約用の認証情報として400で拒否する。
- FR-6: ログインしたアカウントが現在のセッションのアカウントと異なる場合は、登録を400で拒否する。
- FR-7: 自分の予約を状態で絞り込み、件数の上限とカーソルを指定して一覧で取得できる。
- FR-8: 待機中の予約は取消でき、投稿済みと失敗の予約は履歴として削除でき、実行中の予約は409で拒否する。
- FR-9: 待機中の予約が20件あるアカウントによる作成は、429で拒否する。
- FR-10: 予約用の認証情報の登録状態を取得でき、待機中の予約がないときに限って削除できる。
- FR-11: 作成に成功すると、予約の識別子と実行時刻を返す。

## 5. 非機能要件

- NFR-1: 入力の検証と API 文書を、1つのスキーマ定義から導出する。
- NFR-2: エラー応答を400・401・404・409・429・500に分類し、すべての応答にキャッシュを禁止する指定を付ける。
- NFR-3: パスワードとトークンを含む文字列を、応答とログに出力する箇所を0件にする。
- NFR-4: 予約の API の経路で、atproto のライブラリを静的に読み込む箇所を0件にする。

## 6. 受け入れ条件

- AC-1 (FR-1): 投稿が0件または101件の予約は400で拒否され、画像を含む2件のスレッドの予約は作成できる。
- AC-2 (FR-1): 動画を含む投稿の予約は400で拒否される。
- AC-3 (FR-2): 実行時刻が4分後または31日後の作成は400になり、10分後と30日後の作成は成功する。
- AC-4 (FR-3): 認証情報が未登録のアカウントによる作成は409になり、予約は保存されない。
- AC-5 (FR-4): アプリパスワードでのログインに成功すると、暗号化されたトークンが保存され、パスワードはどこにも保存されない。
- AC-6 (FR-5): ログインで得たセッションがメインパスワードのものであるとき、400になり何も保存されない。
- AC-7 (FR-6): パスワードのログイン先が別のアカウントのとき、400になり何も保存されない。
- AC-8 (FR-7): 他のアカウントの予約は一覧に含まれず、状態の指定で絞り込まれ、続きがあるときはカーソルが返る。
- AC-9 (FR-8): 待機中の予約の取消で画像も削除され、投稿済みの予約の削除は成功し、実行中の予約の削除は409になる。
- AC-10 (FR-9): 待機中の予約が20件あるアカウントの21件目の作成は429になる。
- AC-11 (FR-10): 登録状態の取得が登録の有無を返し、待機中の予約があるときの削除は409、ないときは成功する。
- AC-12 (FR-11): 作成に成功すると、200と識別子と実行時刻が返る。
- AC-13 (NFR-1): 作成・一覧・取消の入力スキーマが、API 文書の生成に使われる定義と同一である。
- AC-14 (NFR-2): 未認証で401、不正な入力で400、他人の予約で404になり、すべての応答にキャッシュを禁止する指定が付く。
- AC-15 (NFR-3): 認証に失敗する登録を実行しても、パスワードとトークンがログと応答に現れない。
- AC-16 (NFR-4): 予約の API の経路が、atproto のライブラリを静的に読み込まない。
