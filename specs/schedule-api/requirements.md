# 予約投稿API 要件定義書

## 1. 目的

利用者が自分の Bluesky アカウントの予約投稿を、作成・一覧・編集・取消できるようにする。投稿時刻に利用者がブラウザを閉じていても投稿できるよう、アプリパスワードで得た予約専用の認証情報を登録させ、その登録と削除も扱う。メインパスワードのサーバー保管は行わない。

## 2. スコープ

### 2.1 対象

- 予約の作成・一覧・内容の取得・置き換え・取消と、失敗した予約の履歴の削除。
- 予約用の認証情報の登録・状態確認・削除と、削除に伴う待機中の予約の取消。
- 実行時刻の範囲と、アカウントごとの予約件数の検証。
- 検証に使う制限値の提供。

### 2.2 対象外

- 予約の実行と PDS への投稿。
- 動画を含む予約。

## 3. 前提

- 前提: schedule-store — 予約と認証情報の保管と取り出しを使う。

## 4. 機能要件

- FR-1: 予約は、1件から100件の投稿・実行時刻・entry の作成指定・投稿ごとの返信と引用の制限・画像を指定して作成でき、成功すると識別子と実行時刻を返す。
- FR-2: 実行時刻は、作成と置き換えの時点から5分後以降14日後以内に限り、範囲外は400で拒否する。
- FR-3: 予約用の認証情報が未登録のアカウントによる予約の作成と置き換えは、409で拒否する。
- FR-4: 予約用の認証情報は、アプリパスワードで新たにログインして得たトークンだけを暗号化して登録し、パスワードを保管しない。
- FR-5: アプリパスワード以外のパスワードで得たセッションと、現在のセッションと異なるアカウントのセッションは、登録を400で拒否する。
- FR-6: 自分の予約を状態で絞り込み、件数の上限とカーソルを指定して一覧で取得できる。
- FR-7: 待機中の予約は取消でき、失敗の予約は履歴として削除でき、実行中の予約は409で拒否する。
- FR-8: 待機中の予約が5件あるアカウントによる作成は、スレッドの投稿の件数によらず429で拒否する。
- FR-9: 予約用の認証情報の登録状態を取得でき、削除すると待機中の予約をすべて取り消し、実行中の予約があるときは409で拒否する。
- FR-10: 実行時刻の範囲・待機中の予約の上限・画像の合計容量の上限・投稿の件数の上限を、制限値として取得できる。
- FR-11: 自分の待機中または失敗の予約について、作成時と同じ形の投稿内容と状態と、添付した画像を番号ごとに取得できる。
- FR-12: 自分の待機中の予約を、作成と同じ入力で実行時刻と内容と画像ごと置き換えられ、実行中になった予約は409で拒否する。

## 5. 非機能要件

- NFR-1: 入力の検証と API 文書を、1つのスキーマ定義から導出する。
- NFR-2: エラー応答を400・401・404・409・429・500に分類し、すべての応答にキャッシュを禁止する指定を付ける。
- NFR-3: パスワードとトークンを含む文字列を、応答とログに出力する箇所を0件にする。
- NFR-4: 予約の API の経路で、atproto のライブラリを静的に読み込む箇所を0件にする。

## 6. 受け入れ条件

- AC-1 (FR-1): 投稿が0件または101件の予約は400で拒否され、画像を含む2件のスレッドの予約は作成できる。
- AC-2 (FR-1): 動画を含む投稿の予約は400で拒否される。
- AC-3 (FR-2): 実行時刻が4分後または15日後の作成は400になり、10分後と14日後の作成は成功する。
- AC-4 (FR-3): 認証情報が未登録のアカウントによる作成は409になり、予約は保存されない。
- AC-5 (FR-4): アプリパスワードでのログインに成功すると、暗号化されたトークンが保存され、パスワードはどこにも保存されない。
- AC-6 (FR-5): ログインで得たセッションがメインパスワードのものであるとき、400になり何も保存されない。
- AC-7 (FR-5): パスワードのログイン先が別のアカウントのとき、400になり何も保存されない。
- AC-8 (FR-6): 他のアカウントの予約は一覧に含まれず、状態の指定で絞り込まれ、続きがあるときはカーソルが返る。
- AC-9 (FR-7): 待機中の予約の取消で画像も削除され、失敗の予約の削除は成功し、実行中の予約の削除は409になる。
- AC-10 (FR-8): 待機中の予約が5件あるアカウントの6件目の作成は、1件の投稿でも3件のスレッドでも429になる。
- AC-11 (FR-9): 登録状態の取得が登録の有無を返し、削除で待機中の予約と画像が消え、実行中の予約があると409になる。
- AC-12 (FR-1): 作成に成功すると、200と識別子と実行時刻が返る。
- AC-13 (NFR-1): 作成・一覧・取得・置き換え・取消の入力スキーマが、API 文書の生成に使われる定義と同一である。
- AC-14 (NFR-2): 未認証で401、不正な入力で400、他人の予約で404になり、すべての応答にキャッシュを禁止する指定が付く。
- AC-15 (NFR-3): 認証に失敗する登録を実行しても、パスワードとトークンがログと応答に現れない。
- AC-16 (NFR-4): 予約の API の経路が、atproto のライブラリを静的に読み込まない。
- AC-17 (FR-10): 制限値の取得が、検証に使う値と同じ実行時刻の範囲と3つの上限を返し、未認証では401になる。
- AC-18 (FR-11): 画像つきの待機中の予約を取得すると、投稿内容と画像の番号が返り、番号で取得した画像が作成時のバイト列と一致する。
- AC-19 (FR-11): 他人の予約と待機中でも失敗でもない予約の内容の取得は404になり、失敗の予約は内容と画像を取得できて状態が失敗と示される。
- AC-20 (FR-12): 待機中の予約を置き換えると、新しい内容と実行時刻で取得でき、置き換え前の画像が削除される。
- AC-21 (FR-12): 実行中の予約の置き換えは409になり、範囲外の実行時刻での置き換えは400になって内容が変わらない。
