# entry API 要件定義書

## 1. 目的

Bluesky投稿の作成と、投稿に紐づくskyshare entryの作成・編集・削除を、1つのAPIで所有権と整合性を保って行えるようにする。

## 2. スコープ

### 2.1 対象

- 1件またはスレッドのBluesky投稿の作成と、同時のentryの作成。
- 既存の投稿からのentryの作成。
- entryの見出しと説明文の編集。
- entryの削除と、紐づくBluesky投稿の削除。

### 2.2 対象外

- entryの一覧の取得。
- entryの作成対象とする投稿の選び方と、代表画像・見出し・説明文の生成。
- 本文中のリンク・メンション・ハッシュタグの自動検出。
- 動画の投稿。

## 3. 前提

- なし

## 4. 機能要件

- FR-1: 1回のリクエストで1件または複数件のスレッドの投稿を作成でき、各投稿はテキスト・リンクカード・最大10枚の画像を持てる。
- FR-2: 画像が4枚以下の投稿は画像形式、5枚以上はギャラリー形式で投稿し、画像とリンクカードを同時に指定した投稿は画像を採用する。
- FR-3: スレッドを自分の既存の投稿への返信として接続でき、返信可否と引用可否を投稿ごとに設定できる。
- FR-4: entryの作成要否と代表画像はリクエスト全体で1組だけ指定でき、代表画像があれば投稿の内容によらずentryを作成する。
- FR-5: 新規投稿で作成するentryの派生元は、常にスレッドの先頭の投稿とする。
- FR-6: 自分の既存の投稿を指定すると、新規投稿を作らずに、その投稿自身を派生元とするentryを作成する。
- FR-7: 自分のentryの見出しと説明文を編集でき、代表画像と派生元は変えない。
- FR-8: 自分のentryを削除でき、指定した場合は派生元から自分が続けて投稿したBluesky投稿もすべて削除する。
- FR-9: 派生元が返信の投稿であるentryに投稿の削除を指定した場合は、entryもBluesky投稿も削除せずに拒否する。
- FR-10: 削除範囲の判定に必要な情報を取得できない場合は何も削除せず、派生元が既に存在しない場合はentryだけを削除する。
- FR-11: Bluesky投稿の削除に失敗しても、entryの削除は成功として扱う。

## 5. 非機能要件

- NFR-1: 自分以外の投稿とentryへの操作を0件とし、クライアントが送るURIはコレクションと所有者を検証してから使う。
- NFR-2: 複数の投稿・gate・entryの作成と複数の投稿の削除は、それぞれ1回の原子的な書き込みで全件成功か全件失敗にする。
- NFR-3: entryの編集で、同時編集による更新の消失を0件にする。
- NFR-4: エラー応答を400・401・404・409・429・500に分類し、キャッシュさせない。
- NFR-5: スレッドの投稿数の上限100件を、投稿の作成と下書きで同じ定数から参照する。
- NFR-6: 入力の検証とAPIドキュメントを、1つのスキーマ定義から導出する。
- NFR-7: アプリ独自の投稿頻度の制限を0件とし、レート制限は連携先の制限だけに従う。

## 6. 受け入れ条件

- AC-1 (FR-1): テキストのみの投稿と画像のみの投稿が混在するスレッドが、1回の書き込みで作成される。
- AC-2 (FR-2): 画像4枚の投稿は画像形式、5枚の投稿はギャラリー形式になり、画像11枚の投稿は400で拒否される。
- AC-3 (FR-2): 画像とリンクカードを両方指定した投稿で、画像が採用される。
- AC-4 (FR-3): 返信先に他人の投稿を指定すると400で拒否され、gateを指定した投稿にだけgateレコードが作られる。
- AC-5 (FR-4): 画像を含まないスレッドでも、代表画像を指定するとentryが1件作成される。
- AC-6 (FR-5): 画像投稿がスレッドの2件目にあっても、entryの派生元がスレッドの先頭の投稿になる。
- AC-7 (FR-6): 既存の自分の投稿を指定すると、その投稿を派生元とするentryが作成され、他人の投稿では400になる。
- AC-8 (FR-7): 自分のentryの見出しと説明文を更新すると200になり、他人のentryでは400になる。
- AC-9 (FR-8): 投稿の削除を指定すると、派生元から続く自分の投稿だけが1回の書き込みで削除され、第三者の返信の先は削除されない。
- AC-10 (FR-9): 派生元が返信の投稿であるentryに投稿の削除を指定すると、409になり何も削除されない。
- AC-11 (FR-10): スレッドの取得が見つからない以外の理由で失敗すると500になり、派生元が存在しない場合はentryだけが削除される。
- AC-12 (FR-11): 投稿の削除が失敗しても、entryの削除は200になる。
- AC-13 (NFR-1): 他人の投稿への返信の接続と、他人のentryの編集・削除が400で拒否される。
- AC-14 (NFR-2): スレッドの2件目で検証に失敗すると、書き込みが1件も行われずに400になる。
- AC-15 (NFR-3): entryの更新で、読み取り時のレコードの識別子を照合条件として書き込む。
- AC-16 (NFR-4): ヘッダの欠落は400、未認証は401、対象のentryが無いときは404になる。
- AC-17 (NFR-5): 投稿の作成と下書きのスキーマが、同じスレッドの上限の定数を参照する。
- AC-18 (NFR-6): 生成したAPIドキュメントの入力定義が、検証に使うスキーマ定義と一致する。
- AC-19 (NFR-7): 連携先がレート制限を返したとき、429になる。
