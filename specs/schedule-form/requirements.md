# 予約投稿の画面 要件定義書

## 1. 目的

利用者が投稿フォームで作った内容に実行日時を指定して予約し、予約の一覧で状態の確認と取消を行えるようにする。予約には予約専用の認証情報が必要であり、その登録と削除の操作も画面で提供する。

## 2. スコープ

### 2.1 対象

- 予約日時の入力と、予約の送信。
- 予約用の認証情報の登録・状態表示・削除の操作。
- 予約の一覧の表示と、取消と履歴の削除の操作。

### 2.2 対象外

- 投稿フォームそのものの入力部品。
- 予約の保管と実行。
- 予約内容の編集。

## 3. 前提

- なし

## 4. 機能要件

- FR-1: 投稿フォームの内容に、実行日時を指定して予約でき、日時の既定値は1時間後とする。
- FR-2: 日時は端末のタイムゾーンで入力して表示し、送信時はタイムゾーンの差を含む形式に変換する。
- FR-3: 現在から5分後より前、または30日後より後の日時では、送信を無効にして理由を表示する。
- FR-4: 予約用の認証情報が未登録のアカウントでは、予約の前にアプリパスワードの入力を求め、登録に成功したら予約を続ける。
- FR-5: 認証情報の入力では、メインパスワードを入力しないよう注意を示し、アプリパスワードの作成方法を案内する。
- FR-6: 予約に成功すると、予約の一覧への案内を表示し、投稿フォームの入力を初期化する。
- FR-7: 予約の一覧は、実行時刻の昇順に、状態・実行時刻・本文の冒頭・投稿の件数を表示する。
- FR-8: 待機中の予約は確認の後に取消でき、投稿済みと失敗の予約は履歴として削除できる。
- FR-9: 失敗の予約には失敗の理由を表示言語の文言で表示し、投稿済みの予約には先頭の投稿へのリンクを表示する。
- FR-10: 予約用の認証情報の登録状態を表示し、待機中の予約がないときに削除できる。
- FR-11: API のエラーを、表示言語の文言で表示する。

## 5. 非機能要件

- NFR-1: 予約に関わるボタンと入力欄の寸法を、縦横とも44ピクセル以上にする。
- NFR-2: 画面の文言を日本語と英語の2言語で持ち、文言の直書きを0件にする。
- NFR-3: パスワード欄を持つ入力で、ユーザー名欄と現在のパスワード欄を同じフォームに1組ずつ置く。
- NFR-4: 送信中は同じ操作を受け付けず、1回の操作で作成される予約を1件以下にする。

## 6. 受け入れ条件

- AC-1 (FR-1): 予約を選ぶと日時の入力が現れ、既定値が現在から1時間後になる。
- AC-2 (FR-2): 端末のタイムゾーンが東京のとき、入力した日時が同じ時刻のタイムゾーンつきの形式で送信される。
- AC-3 (FR-3): 4分後と31日後の日時では送信できず理由が表示され、10分後と30日後では送信できる。
- AC-4 (FR-4): 認証情報が未登録のとき、パスワードの入力が先に現れ、登録に成功すると予約が送信される。
- AC-5 (FR-5): 認証情報の入力に注意の文言とアプリパスワードの案内が表示される。
- AC-6 (FR-6): 予約に成功すると一覧への案内が現れ、投稿フォームの本文が空になる。
- AC-7 (FR-7): 3件の予約が実行時刻の昇順で並び、各行に状態と本文の冒頭と件数が表示される。
- AC-8 (FR-8): 取消の確認を拒否すると予約が残り、承諾すると待機中の予約が一覧から消える。
- AC-9 (FR-9): 失敗の予約に理由の文言が表示され、投稿済みの予約にリンクが表示される。
- AC-10 (FR-10): 認証情報の登録状態が表示され、待機中の予約があると削除が無効になる。
- AC-11 (FR-11): API が409を返すと、日本語と英語のそれぞれの文言でエラーが表示される。
- AC-12 (NFR-1): 予約に関わるボタンと入力欄が、縦横とも44ピクセル以上である。
- AC-13 (NFR-2): 日本語と英語の辞書の文言のキーの集合が一致し、画面に直書きの文言がない。
- AC-14 (NFR-3): 認証情報の入力が、可視のユーザー名欄と現在のパスワードとして扱う欄を同じフォームに持つ。
- AC-15 (NFR-4): 送信中に確定操作を2回行っても、予約の作成の呼び出しが1回だけである。
