# プルダウン（Dropdown）自前実装 要件定義書

## 1. 背景・目的

アプリ内のプルダウンはブラウザ標準の `<select>` に依存しており、次の制約がある。

- 選択肢の見た目をテキスト以外にできない（言語選択で国旗を並べられない）。
- 約180件ある言語一覧で、一覧の見た目・スクロール・絞り込みを制御できない。
- OS・ブラウザごとに一覧の見た目と挙動が異なる。

本機能は、`@` や `#` の入力で表示される候補フローティングと同じ見た目・操作感を持つ、アプリ共通のプルダウンを提供する。標準 `<select>` による既存プルダウンはすべてこれに置き換える。

## 2. 用語定義

| 用語           | 意味                                                                                                                             |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| トリガー       | プルダウンを開閉するボタン。閉じている間は現在の選択項目を表示する。                                                             |
| パネル         | 開いたときに表示される、選択肢一覧を含むフローティング領域。                                                                     |
| 選択肢         | 値（value）・表示ラベル（label）を持つ1項目。無効（disabled）にできる。                                                          |
| アクティブ項目 | キーボード/マウスでハイライトされている選択肢。確定前の候補。                                                                    |
| 検索モード     | 検索付きプルダウンで、トリガー自身が入力欄になり、入力した文字で選択肢を絞り込む状態。一覧から選ぶ通常の状態は一覧モードと呼ぶ。 |

## 3. スコープ

### 3.1 対象

- 共通プルダウン部品の新設。
- 既存4種（投稿言語・表示テーマ・自己ラベル・表示件数）の共通プルダウンへの置き換え。
- 投稿言語選択における、選択肢ごとの国旗（絵文字）表示。
- `@`/`#` 候補フローティングと共通プルダウンの間での、選択肢行の共通化。

### 3.2 対象外

- 複数選択。
- 選択肢のグループ見出し。
- スマホ幅でのボトムシート表示（同じパネル表示を使う）。
- 国旗画像（SVG）の導入。国旗は絵文字とし、国旗絵文字を描画できない環境では2文字の国コード表記になることを許容する。
- 選択肢の非同期取得・無限スクロール。

## 4. 機能要件

### FR-1: 開閉

- トリガーの操作（クリック・タップ）でパネルを開ける。検索なしのプルダウンは、開いている間の再操作で閉じる。検索付きのプルダウンは、開いている間の再操作で検索モードに入る（FR-5）。
- パネルは次のいずれかで閉じる: 選択肢の確定 / パネル外のクリック・タップ / Esc / Tab によるフォーカス移動。
- ページや祖先要素のスクロール、ウィンドウのリサイズ、ソフトウェアキーボードの表示・非表示では閉じない。パネルはトリガーに付いて動く。
- 無効状態（disabled）のプルダウンは開けない。
- 閉じたとき、フォーカスはトリガーに戻る（パネル外クリックで閉じた場合を除く）。

### FR-2: 表示位置

- パネルはトリガーの直後に、トリガーの右端に揃えて表示する。左へはみ出す場合は左端に揃える。パネルの最小幅はトリガーの幅とする。
- パネルを開閉しても、他のコンポーネントの位置・大きさ（レイアウト）は変わらない。
- パネルは、親要素のクリップ（`overflow`）で見切れない。
- トリガーの下に十分な空きがなく、上の方が広い場合は、トリガーの上に表示する。空きは、画面（ソフトウェアキーボードを除いた見えている範囲）と、トリガーを含むスクロール枠（モーダルなど）の範囲の共通部分で判断する。一覧の高さはその空きに収める。
- 画面のスクロール・ソフトウェアキーボードの表示中も、パネルはトリガーの直後（または直前）に付いて表示される。ずれたり、トリガーに重なったりしない。
- 投稿フォームのモーダル内で開いた場合も、モーダルより前面に表示する。

### FR-3: スクロール

- 選択肢が多く最大高さを超える場合、パネル内の一覧が縦スクロールできる。同時に表示する行数は最大5行とし、それを超える選択肢は一覧内をスクロールして見る。最大高さは5行分の高さと、トリガー上下の画面残余の小さい方とする。
- 開いたとき、選択中の項目が一覧内で見える位置になる。
- キーボードでアクティブ項目を動かしたとき、アクティブ項目が常に一覧内で見える位置になる。

### FR-4: キーボード操作

- トリガーにフォーカスがある状態で Enter / Space / ↓ / ↑ によりパネルを開く。開いた時点のアクティブ項目は選択中の項目とする。
- パネルが開いている間、↓/↑ でアクティブ項目を移動する（端で循環しない）。Home/End で先頭/末尾へ移動する。無効の選択肢は飛ばす。
- Enter（検索なし、または検索付きの一覧モードでは Space も）でアクティブ項目を確定する。
- 検索なしの場合、文字キーの入力で、ラベルがその文字列で始まる次の選択肢へアクティブ項目を移動する（連続入力は1つの文字列として扱う）。
- IME変換中の Enter・矢印キーは操作として扱わない。

### FR-5: 検索（検索付きプルダウン）

- プルダウンごとに、検索の有無を選べる。既定は無し。検索のためにパネル内へ入力欄は置かない。入力欄はトリガー自身である。
- 検索付きのプルダウンは、1回目のクリック・タップで一覧モードでパネルを開く。このときソフトウェアキーボードは表示しない。開いている間は、一覧モードでもトリガー（入力欄）は現在値ではなく入力待ちの placeholder を表示する（閉じている間は現在値）。
- パネルが開いている間にトリガーをもう一度クリック・タップすると、検索モードに入る。パネルは閉じない。一覧モードで開いている間にキーボードで文字を入力した場合も、検索モードに入り、その文字が入力される。
- 検索モードに入った直後（入力が空）は、トリガーが空になり入力できることを示す placeholder を表示する。パネルは入力待ちを示す専用の文言を、候補が0件のときと同じ枠で表示し、選択肢は表示しない。
- 入力すると、入力した文字列を含む選択肢のみが一覧に表示される（大文字小文字・全角半角を区別しない）。入力が1文字以上で該当が0件の場合は、その旨のメッセージを表示する。
- 絞り込み対象の文字列は、選択肢のラベルを既定とし、選択肢ごとに別の文字列（例: 言語コード）を追加で指定できる。
- 絞り込み結果が変わったとき、アクティブ項目は結果の先頭の有効な選択肢になる。
- 選択肢を確定すると、パネルを閉じ、トリガーは新しい選択項目の表示になる。
- 確定できる選択肢が無い状態（入力が空、または該当が0件）で確定操作（Enter）をしても何も確定せず、直前の選択項目のままとする。確定せずに閉じた場合（Esc・パネル外クリック・Tab）も、入力は破棄し、トリガーは直前の選択項目の表示に戻る。
- 検索モードでキーボードの完了操作などで入力欄のフォーカスだけが外れた場合、入力が空なら一覧モードへ戻り、入力済みなら入力と絞り込み結果を残す。パネル外をタップすると閉じて入力を破棄する。
- 検索モードで入力欄にフォーカスがある間も、スクロールやソフトウェアキーボードの出入りでパネルは閉じず、トリガーに付いて表示される（FR-1・FR-2）。
- パネルを開き直したとき、検索は一覧モード・入力は空に戻る。

### FR-6: 選択肢の表示

- 選択肢は、ラベル文字列に加えて任意の表示内容（アイコン・国旗・補足テキスト等）を持てる。表示内容は一覧とトリガーの現在値表示に使われ、トリガー用に一覧と異なる表示内容を指定することもできる。検索付きのトリガーは入力欄のため、現在値の表示は文字列（国旗絵文字を含められる）で指定する。
- 選択中の項目は一覧内で他と区別できる。
- アクティブ項目は一覧内で他と区別できる。
- 長いラベルは省略表示とし、パネルの高さは崩れない。
- 選択肢が0件のときは、メッセージのみを表示する。

### FR-7: トリガー表示

- 閉じている間と一覧モードの間は、現在の選択項目の表示内容を表示し、開閉を示す矢印を持つ。
- 現在値が選択肢に存在しない場合は、現在値の文字列、または指定されたプレースホルダを表示する。
- 横幅は、固定幅と、選択内容に合わせた可変幅のいずれかを選べる。
- 見た目は既存プルダウン（`<select>`）と同じ外観（枠・角丸・配色・矢印）を維持する。

### FR-8: 投稿言語の国旗

- 投稿言語選択では、各言語の選択肢に、その言語を代表する国の国旗（絵文字）を言語名の前に表示する。
- 複数の国にまたがる言語は、代表国を1つ定めて表示する。
- 国に対応づけられない言語（エスペラント語、ラテン語など）は国旗なしとし、一覧内でラベルの位置が揃う。
- 国旗は、トリガーの現在値表示にも表示する（国旗なしの言語は表示しない）。

### FR-9: 既存プルダウンの置き換え

- 投稿言語・表示テーマ・自己ラベル・表示件数の4種は、共通プルダウンを使う。
- 各プルダウンの選択肢の内容、既定値、値の意味、呼び出し側から見た入出力の型は変更しない。
- 投稿言語は検索付き（トリガーが入力欄）。他の3種は検索なしで、従来どおりボタンのトリガーとする。
- 自己ラベルの「ラベルなし」は通常の選択肢として選択できる。

### FR-10: `@`/`#` 候補フローティングとの選択肢行の共通化

- `@`/`#` 候補フローティングと共通プルダウンは、同一の選択肢行の見た目・ハイライト挙動を使う。
- 共通化によって、`@`/`#` 候補の既存の挙動（キャレット位置への表示、mousedown での確定、フォーカス維持）は変わらない。

## 5. 非機能要件

- NFR-1: アクセシビリティ。スクリーンリーダーに、現在値・開閉状態・選択項目・アクティブ項目が伝わること（WAI-ARIA の listbox/combobox パターンに準拠）。
- NFR-2: SSG。サーバー描画時（`document` 不在）でも例外を出さず、閉じた状態のトリガーのみを描画する。
- NFR-3: 性能。約180件の選択肢を表示・絞り込みしても、入力に対する応答が体感で遅延しないこと。
- NFR-4: 既存の共通コンポーネント規約（ディレクトリ構成・コーディング規則・コメント規定）に従うこと。

## 6. 受け入れ条件

1. 4種のプルダウンがすべて共通プルダウンになり、リポジトリ内に `<select>` が残っていない。
2. 投稿言語で「日本語」を選ぶと、トリガーに日本国旗と「日本語」が表示され、言語コード `ja` が呼び出し側へ渡る。
3. 投稿言語のパネルで 180件超の選択肢をスクロールでき、パネルがビューポートからはみ出さない。
4. 投稿言語で、1回目のタップは一覧モードで開き（キーボードは出ない）、開いたまま再タップすると検索モードに入る（パネルは閉じず、入力待ちの文言が出る）。「ko」または「한국어」と入力すると該当言語のみに絞り込まれ、確定せず閉じると直前の選択に戻る。
5. キーボードのみで、開く→移動→確定→閉じるが完結し、確定後フォーカスがトリガーに戻る。
6. 日本語IMEの変換確定の Enter で、選択肢が確定されない。
7. `@`/`#` 候補フローティングの既存E2Eテストがすべて通る。
