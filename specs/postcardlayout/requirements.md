# 投稿カード表示・画像拡大 要件定義書

## 1. 背景・目的

Skyshare Entry の詳細ページ（`/entries/[slug]`）は、投稿全体を1枚の枠に収め、画像を原寸で縦に並べている。一方 Timeline（`/`）は投稿ごとのカードで表示している。本機能は、Entry詳細ページを Timeline と同じ「投稿カード」形式の表示に揃え、画像をサムネイル表示にしてタップで拡大できるようにする。あわせて、投稿カードと画像表示を Timeline と Entry詳細ページで共通の部品として扱う。

## 2. 用語定義

| 用語              | 意味                                                                                                                                 |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| 投稿カード        | 1件の Bluesky 投稿を、作者・日時・本文・画像とともに1枚のカードとして表示するもの。                                                  |
| ヘッダーカード    | Entry詳細ページ上部に表示する、Entry自体の情報（見出し・キャプション等）のカード。                                                   |
| サムネイル        | 投稿カード内に表示する、拡大前の小さな画像表示。                                                                                     |
| 拡大表示          | サムネイルをタップした際に画面全体へ重ねて表示する、画像の拡大ビュー。                                                               |
| スレッド由来Entry | `source` 投稿から Entry 所有者自身の後続投稿が連なっている Entry（[specs/entry/frontend FR-4](../entry/frontend/requirements.md)）。 |

## 3. スコープ

### 3.1 対象

- Entry詳細ページの投稿・スレッドのカード表示。
- 投稿カード内の画像サムネイル表示と拡大表示。
- Timeline の投稿カードへの、同じサムネイル表示・拡大表示の適用（Skyshare Entry を持つ投稿は代表画像の表示）。
- 上記で共通利用する表示部品の整理。

### 3.2 対象外

- Entry詳細ページ以外のページの下部余白。
- Entry作成・削除・共有など、投稿カードの操作系機能の変更。
- Entry詳細ページの取得ロジック（スレッド抽出規則、404/500等のステータス判定）の変更。
- Timeline カード全体の高さ・折りたたみ方針（画像の表示サイズを含む）。本機能導入後の見た目を確認したうえで、別途要件として定める。
- 画像以外のメディア（動画等）の表示。

## 4. 機能要件

### FR-1: Entry詳細ページの投稿カード表示

- Entry詳細ページは、ヘッダーカードと、投稿カード（1件以上）で構成する。
- ヘッダーカードには、Entryの見出し、Entry自体に設定されたキャプション、Entry作成日時を表示する。リアクション数はヘッダーカードには表示せず、FR-8 のとおり各投稿カードに表示する。Entryのカード画像（View）も表示する（拡大表示は行わない）。スレッド由来であることを示すバッジは表示しない。
- 投稿カードには、作者のアバター・表示名・ハンドル、投稿日時、本文、画像を表示する。各投稿カードから、その投稿のBlueskyページを開ける。
- 本文が空の投稿では本文領域を表示しない。画像が無い投稿では画像領域を表示しない。

### FR-2: スレッドのカード表示

- スレッド由来Entryでは、スレッド内の各投稿を独立した投稿カードとして、投稿順（古い→新しい）に縦に並べる。
- 隣り合う投稿カード同士が連続した投稿であることを、視覚的に判別できるようにする。
- 折りたたみは行わず、すべての投稿カードを常に展開して表示する。
- 単発投稿由来Entryは、投稿カード1件のみを表示する。

### FR-3: 画像サムネイル表示

- 1投稿に添付された画像は、本文の下にサムネイルとして表示する。原寸表示は行わない。
- 画像が4枚以下の場合は、Bluesky と同様の、表示領域の比率を固定したサムネイルグリッドとし、画像は領域に合わせてクロップする。枚数ごとの構成は次のとおり。
  - 1枚: 1つの領域に表示する。
  - 2枚: 横に2つ並べる。
  - 3枚: 左に1枚、右に2枚を縦に並べる。
  - 4枚: 2×2に並べる。
- 画像が5枚以上の場合は、グリッドではなく、本文の下に高さを固定した横スクロールの1行として全画像（最大10枚）を並べる。各サムネイルはその画像の縦横比を維持し、クロップしない。
- 画像の読み込み完了前後で、カードの高さが変動しないこと。
- 各サムネイルには、その画像の代替テキストを設定する。

### FR-4: 画像の拡大表示

- サムネイルをタップ（クリック）、またはキーボードで操作すると、その画像を画面全体に重ねて拡大表示する。
- 拡大表示中は、同じ投稿内の他の画像へ、左右スワイプ・左右矢印キー・前後ボタンで切り替えられる。画像が1枚の場合は切り替え操作を表示しない。
- 拡大表示中は、画像の代替テキストと、複数枚の場合は「現在位置/全枚数」を表示する。
- 背景のタップ、閉じるボタン、Escキーのいずれかで閉じられる。
- 拡大表示中は、背面のページがスクロールしない。
- 拡大画像は、画面に収まるよう縦横比を維持して表示する。

### FR-5: Timelineでの画像サムネイル・拡大表示

- Timeline の投稿カードの画像表示は、その投稿が Skyshare Entry を持つかどうかで次のように分ける。
  - Skyshare Entry が存在する投稿（スレッドの場合はルート投稿）: 添付画像の代わりに、そのEntryの代表画像（visual）を1枚表示する。この画像には拡大表示を設けない（タップしても拡大しない）。元の Bluesky 投稿が削除済みで添付画像を取得できないEntryも同様に visual を表示する。
  - Skyshare Entry が存在しない投稿（スレッドの返信投稿を含む）: FR-3 と同じサムネイル表示を行い、FR-4 と同じ拡大表示ができる。
- 画像を持たない投稿（かつ Entry も持たない投稿）のカードに、画像領域を表示しない。

### FR-6: 表示部品の共通化

- 投稿カードの表示（作者・日時・本文・画像）は、Timeline と Entry詳細ページで同一の部品を使い、同じ見た目になる。
- 画像のサムネイル表示と拡大表示は、投稿カード以外の画面からも単独で利用できる部品とする。
- Entry詳細ページの単発投稿表示とスレッド表示は、重複した表示実装を持たず、投稿カードの並びとして1つの実装で表現する。

### FR-7: 既存の表示・機能の維持

- Entry詳細ページの次の挙動は変更しない: 元の投稿が削除済みの場合の案内表示（保存された内容のみの表示）、404/500/503 のエラーペイン、SNS向けのメタ情報（タイトル・説明・カード画像）。
- Timeline 投稿カードの操作（Blueskyで開く・共有・Entry作成・削除・Entryを開く）の動作は変更しない。

### FR-8: 投稿ごとのリアクション表示

- Entry詳細ページでは、リアクション数（いいね・リポスト・リプライ・引用）を、各投稿カードにその投稿自身の値で表示する。スレッド由来Entryでは、すべての投稿カードがそれぞれの値を表示する。
- 元の Bluesky 投稿が削除済みで投稿カードが存在しない場合、リアクション数は表示しない。

### FR-9: ページ下部の余白（フッター）

- Entry詳細ページの最下部に、内容を持たない余白領域（フッター）を設ける。X アプリ内ブラウザ等で画面下部にアプリ側のUIが重なっても、最後の投稿カードやリアクション表示が隠れず最後まで閲覧できること。
- 余白は、端末のセーフエリア（画面下端の切り欠き・ホームインジケータ領域）を含めた高さを確保する。
- この余白は、エラーペイン（404/500/503）を表示する場合を含め、Entry詳細ページ全体で共通に設ける。

## 5. 非機能要件

### NFR-1: SSRと初期表示

- Entry詳細ページは Cloudflare Workers 上で SSR される。サムネイルを含む投稿カードは、JavaScript の実行前（SSR結果のHTML）の時点で表示されること。拡大表示のみ JavaScript に依存してよい。

### NFR-2: アクセシビリティ

- サムネイルと、拡大表示の各操作（前へ・次へ・閉じる）は、キーボードのみで操作でき、スクリーンリーダー向けの名前を持つ。
- 拡大表示は、開いている間キーボードフォーカスが拡大表示内に留まり、閉じると元のサムネイルにフォーカスが戻る。

### NFR-3: レスポンシブ・テーマ

- モバイル幅（360px）からデスクトップ幅まで、横方向にページがスクロールしない（5枚以上の横スクロール領域内を除く）。
- 既存のライト/ダークテーマ・デザイントークンに従う。

## 6. 受け入れ条件

- [ ] 単発投稿由来Entryの詳細ページが、ヘッダーカード＋投稿カード1件で表示され、画像が原寸ではなくサムネイルで表示される（FR-1, FR-3）
- [ ] スレッド由来Entryの詳細ページが、投稿ごとの独立カードとして古い順に縦に並び、カード間が連続して見える。すべて展開済みである（FR-2）
- [ ] 画像1〜4枚の投稿が、枚数ごとに FR-3 の構成で、比率固定・クロップのサムネイルで表示される（FR-3）
- [ ] 画像5枚以上の投稿が、固定高さの横スクロール1行で全画像を表示し、各画像が縦横比を維持している（FR-3）
- [ ] サムネイルのタップで拡大表示が開き、左右操作で同一投稿内の画像を切り替えられ、代替テキストと位置が表示される（FR-4）
- [ ] 背景タップ・閉じるボタン・Escのいずれでも拡大表示が閉じ、フォーカスが元のサムネイルへ戻る（FR-4, NFR-2）
- [ ] 拡大表示中に背面のページがスクロールしない（FR-4）
- [ ] 1枚の画像の拡大表示に、切り替え操作と位置表示が出ない（FR-4）
- [ ] Timeline で、Skyshare Entry を持つ投稿（スレッドのルート投稿を含む）に、元画像ではなく visual が1枚表示され、タップしても拡大表示が開かない（FR-5）
- [ ] Timeline で、Skyshare Entry を持たない投稿（スレッドの返信投稿を含む）のサムネイル表示と拡大表示が動作する（FR-5）
- [ ] 元投稿が削除済みで画像を持たないEntryが、Timeline で visual を1枚表示する（FR-5）
- [ ] 元投稿が削除済みのEntry詳細ページで、従来どおり案内文と保存済みの内容のみが表示される（FR-7）
- [ ] 404/500/503 のエラーペインとメタ情報が従来どおりである（FR-7）
- [ ] Entry詳細ページのヘッダーカードにリアクション数が表示されず、各投稿カードにその投稿自身のリアクション数が表示される。スレッド由来Entryでは全投稿カードに表示される（FR-8）
- [ ] 元投稿が削除済みのEntry詳細ページに、リアクション数が表示されない（FR-8）
- [ ] Entry詳細ページ最下部に余白領域があり、最後のカードとページ下端の間に端末のセーフエリアを含む余白がある。エラーペイン表示時も同様である（FR-9）
- [ ] Timeline 投稿カードの既存操作（Blueskyで開く・共有・Entry作成・削除・Entryを開く）に regression が無い（FR-7）
- [ ] JavaScript を無効にした状態でも、Entry詳細ページの投稿カードとサムネイルが表示される（NFR-1）
- [ ] 360px幅で、ページ全体に横スクロールが発生しない（NFR-3）
