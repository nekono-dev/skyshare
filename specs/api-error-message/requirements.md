# APIエラーの文言 要件定義書

## 1. 目的

APIのエラーを表示言語の文言で利用者へ伝え、APIの応答から利用者向けの文言を取り除いて言語に依存しない形に統一する。

## 2. スコープ

### 2.1 対象

- APIのエラー応答の形式。
- HTTPステータスとエラーコードからの文言の決定。
- 通信自体の失敗の文言。

### 2.2 対象外

- 文言の辞書と翻訳の規則。
- API固有のエラー条件そのもの。

## 3. 前提

- なし

## 4. 機能要件

- FR-1: APIのエラー応答は利用者向けの文言を含まず、HTTPステータスと言語に依存しない英語の固定文字列だけを返す。
- FR-2: クライアントは、エラー応答のHTTPステータスから表示言語の文言を決めて表示する。
- FR-3: 同じHTTPステータスでも画面ごとに意味が異なる場合は、画面の種別ごとに文言を分ける。
- FR-4: ログイン時にアカウント数が上限に達している場合はステータス409で応答し、ログイン画面に上限に達した旨を表示する。
- FR-5: 個別の文言を持たないステータスのエラーは、汎用の失敗の文言を表示する。
- FR-6: 通信自体が失敗した場合は、サーバーに接続できない旨の文言を表示する。
- FR-7: 一覧や取得処理の失敗は、サーバーの返すエラー文字列を表示せず、その処理に固有の文言を表示する。
- FR-8: 投稿APIが返すエラーコードは文言に変換して表示し、未知のコードには投稿失敗の汎用の文言を表示する。

## 5. 非機能要件

- なし

## 6. 受け入れ条件

- AC-1 (FR-1): サーバーが固定の英語文字列だけを返した409応答で、ログイン画面に表示言語の文言が表示される。
- AC-2 (FR-2): 400・401・403・404・409・429の各ステータスに、それぞれの文言キーが対応する。
- AC-3 (FR-3): ログイン画面では、409がアカウント数上限、429がレート制限、その他がログイン失敗の文言になる。
- AC-4 (FR-4): ログイン時に409が返ると、日本語・英語の各表示言語でアカウント数上限の文言が表示される。
- AC-5 (FR-5): 未知のステータスに汎用の失敗の文言キーが対応する。
- AC-6 (FR-6): ログイン時に通信が失敗すると、接続できない旨の文言が表示される。
- AC-7 (FR-7): タイムラインの取得に失敗すると、サーバーのエラー文字列ではなく読み込み失敗の文言が表示される。
- AC-8 (FR-8): 投稿APIが200以外とエラーコードを返すと、そのコードに対応する文言キーで失敗となる。
