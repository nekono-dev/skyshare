# 不具合報告と機能提案のフォーム 要件定義書

## 1. 目的

利用者が不具合の報告と新機能の提案を1つのフォームから送れるようにし、送る内容と自動で添える情報を送信の前に確かめられるようにする。

## 2. スコープ

### 2.1 対象

- 報告と提案のページと、設定のページからの導線。
- 種別の切り替えと、種別ごとの入力欄。
- 環境の情報の収集と、共有と公開の注記。
- 送信と、結果の表示。

### 2.2 対象外

- 入力の検証と Issue の登録。
- スクリーンショットの添付。

## 3. 前提

- 前提: feedback-api — 送信先の受付と、入力の上限と再現の頻度の値を使うため
- 前提: counted-text-input — 文字数カウンタ付きの入力欄を使うため

## 4. 機能要件

- FR-1: 報告と提案のページは、サイドバーとフッターナビのない単独のページとし、設定のページのヘルプへのリンクの下からリンクされる。
- FR-2: 未ログインのときはフォームを出さず、ログインが必要なことと、ログインのページへのリンクを示す。
- FR-3: 種別はラジオボタンで不具合と新機能の提案を切り替え、入力欄の構成だけを変えて、送信の仕組みは共通とする。
- FR-4: 件名は1行の入力欄とし、見出しは不具合なら「不具合を端的に説明」、新機能の提案なら「新機能を端的に説明」とする。
- FR-5: 不具合は操作した内容の複数行の欄と再現の頻度の4つの選択肢を、新機能の提案は機能の内容と任意の技術的な補足の複数行の欄を示す。
- FR-6: 文章の入力欄はすべて文字数カウンタ付きとし、件名は100文字、本文の各欄は2000文字を上限として表示する。
- FR-7: 必須の項目が空白だけか、上限を超えるか、送信中のときは、送信のボタンを押せなくする。
- FR-8: フォームに、Bluesky のハンドルと環境の情報が自動で収集されて開発者に共有され、GitHub で公開されることを注記し、送る値を一覧で示す。
- FR-9: 環境の情報は、OS・ブラウザ・ホーム画面から起動したか・ブラウザの識別文字列・画面の版とコミットとする。
- FR-10: 送信に成功したら作成した Issue へのリンクを示して入力を空にし、失敗したら状態に応じた文言を示して入力を残す。
- FR-11: 文言は表示言語に合わせて切り替える。

## 5. 非機能要件

- なし

## 6. 受け入れ条件

- AC-1 (FR-1): 設定のページのリンクから報告のページが開き、サイドバーとフッターナビが表示されない。
- AC-2 (FR-2): 未ログインで開くと、フォームがなく、ログインのページへのリンクが表示される。
- AC-3 (FR-3): 新機能の提案に切り替えると、操作した内容と再現の頻度が消え、機能の内容と技術的な補足が表示される。
- AC-4 (FR-4): 件名が1行の入力欄であり、種別を切り替えると見出しが変わる。
- AC-5 (FR-5): 不具合を選ぶと、操作した内容の複数行の欄と再現の頻度の4つの選択肢が表示される。
- AC-6 (FR-6): 件名の欄に「件数/100」、本文の各欄に「件数/2000」のカウンタが表示される。
- AC-7 (FR-7): 件名が空のとき送信のボタンが押せず、必須の項目を埋めると押せ、上限を超えると再び押せない。
- AC-8 (FR-8): 注記にハンドルの共有と GitHub での公開が記載され、送る値の一覧にログイン中のハンドルが載る。
- AC-9 (FR-9): 識別文字列とホーム画面からの起動の状態から、OS とブラウザの名前と起動の形態が求められる。
- AC-10 (FR-10): 送信が成功すると Issue へのリンクが表示されて入力が空になり、429のときは時間を置く旨が表示されて入力が残る。
- AC-11 (FR-11): 英語の表示では、ページの見出しと送信のボタンが英語になる。
