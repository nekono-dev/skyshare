# 予約ストア 要件定義書

## 1. 目的

予約投稿の内容・実行状態・添付画像・予約用の認証情報を、利用料金の発生しない無料枠の範囲で保管し、実行時刻が到来した予約を安全に取り出せるようにする。利用者の投稿と entry は引き続き利用者自身の PDS に保管し、ここで保管するのは実行前の予約と、実行に必要な最小限の認証情報だけである。

## 2. スコープ

### 2.1 対象

- 予約の保存・取得・一覧・置き換え・削除と状態の遷移。
- 予約用の認証情報の暗号化保管。
- 添付画像の一時保管と削除。
- 実行の進捗の保持と、中断した実行の再開。

### 2.2 対象外

- 予約の実行と PDS への投稿。
- 予約を操作する HTTP の API と画面。
- 動画の保管。

## 3. 前提

- なし

## 4. 機能要件

- FR-1: 予約は、所有アカウント・実行時刻・投稿内容・状態を持ち、状態は待機・実行中・失敗の3種とし、成功した予約は履歴に残さない。
- FR-2: 予約の取得・一覧・削除・待機中と失敗の一括削除は、常に所有アカウントを条件に含め、他のアカウントの予約を返さず削除しない。
- FR-3: 実行時刻が到来した待機中の予約を、実行時刻の早い順に指定件数だけ実行中として取り出せる。
- FR-4: 予約用の認証情報はアカウントごとに1件、認可の途中の状態は10分だけ暗号化して保管し、平文を保管せず出力しない。
- FR-5: 認証情報は、予約がなく30日使われないときと失効したときに消して再度の許可が必要な印に替え、印は180日後に、行は所有アカウントの指示で削除できる。
- FR-6: 添付画像は予約ごとに一時保管し、保管の上限を超える画像は拒否し、保管した画像を呼び出し側が削除できる。
- FR-7: 実行の進捗として、アップロード済みの画像と作成済みの投稿を予約ごとに保持し、中断後に続きから再開できる。
- FR-8: 実行中のまま指定の時間更新されない予約を、待機中へ戻せる。
- FR-9: 失敗の予約は、失敗から7日が過ぎたものを削除できる。
- FR-10: 実行中の予約を、進捗を保ったまま待機中へ戻せ、再試行の回数を数えるかどうかを選べる。
- FR-11: 待機中の予約に限り、実行時刻・投稿内容・画像を置き換えられ、実行中になった予約は置き換えない。
- FR-12: 保管した画像を、予約の所有アカウントと画像の番号を指定して読み出せる。

## 5. 非機能要件

- NFR-1: 1回の取り出しは5件以内とし、1予約が保管する画像は合計10メガバイト以内にする。
- NFR-2: 同じ平文の認証情報を2回暗号化したとき、暗号文が一致する件数を0件にする。
- NFR-3: 予約1件の保存・取得・置き換えは、データベースへの問い合わせ3回以内で完了する。
- NFR-4: 削除されずに残った画像を、保管から15日以内に自動で削除する。
- NFR-5: 登録状態の取得が走査する他のアカウントの予約の行を、予約の件数によらず0行にする。

## 6. 受け入れ条件

- AC-1 (FR-1): 状態が3種以外の予約は保存できず、新規の予約は待機として保存される。
- AC-2 (FR-2): 別のアカウントの予約を取得・一覧・削除しても、0件が返り何も削除されない。
- AC-3 (FR-3): 実行時刻が過去の待機中の予約3件を2件指定で取り出すと、早い2件が実行中になり残りは待機のままである。
- AC-4 (FR-3): 同じ予約を2回続けて取り出しても、2回目には含まれない。
- AC-5 (FR-4): 保管した認証情報の暗号文に平文のトークンが含まれず、復号すると元の値に戻る。
- AC-6 (FR-5): 待機中の予約が残るか最後の使用から30日以内なら認証情報は残り、どちらにも当たらないと印になり、印は最後の使用から180日を超えると削除される。
- AC-7 (FR-6): 予約を削除すると、その予約の画像がすべて削除される。
- AC-8 (FR-7): 進捗を保存した予約を取り出し直すと、保存した進捗が返る。
- AC-9 (FR-8): 実行中のまま指定の時間を超えた予約が待機に戻り、超えていない予約は実行中のままである。
- AC-10 (FR-9): 失敗から7日を超えた予約だけが削除され、待機中の予約は残る。
- AC-11 (NFR-1): 6件が到来していても1回の取り出しは5件までで、合計10メガバイトを超える画像の保管は拒否される。
- AC-12 (NFR-2): 同じトークンを2回暗号化した結果が一致しない。
- AC-13 (NFR-3): 予約1件の保存・取得・置き換えでデータベースへの問い合わせが3回以内である。
- AC-14 (FR-10): 実行中の予約を戻すと進捗が保たれ、回数を数える指定のときだけ再試行の回数が1増える。
- AC-15 (FR-2): 待機中と失敗の予約の一括削除で、自分の待機中と失敗の予約が削除され、他のアカウントの予約と自分の実行中の予約が残る。
- AC-16 (FR-5): 所有アカウントの指示で、待機中の予約が残っていても認証情報が削除される。
- AC-17 (FR-11): 待機中の予約を置き換えると新しい実行時刻と内容と画像のキーが保存され、実行中の予約は置き換わらない。
- AC-18 (FR-12): 保管した画像を番号で読み出すと書き込んだバイト列が返り、他のアカウントを指定すると返らない。
- AC-19 (NFR-4): 画像のバケットに、保管から15日で削除するライフサイクルの設定が手順として記載されている。
- AC-20 (FR-4): 認可の途中の状態は、所有アカウントで10分以内に1回だけ取り出せ、別のアカウント・2回目・期限後には取り出せない。
- AC-21 (FR-5): 失効を記録すると認証情報を取り出せず再度の許可が必要と返り、許可を得て保管し直すと印が外れて許可の時刻が更新される。
- AC-22 (NFR-5): 登録状態の取得の問い合わせが、アカウントと状態で絞る索引だけで予約の表を検索し、全件の走査や状態だけの索引を使わない。
