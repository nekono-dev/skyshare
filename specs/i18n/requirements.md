# 多言語対応（日本語・英語） 要件定義書

## 1. 背景・目的

アプリの表示文言は日本語に固定されている。日本語・英語の2言語で利用できるようにし、利用者が表示言語を選べるようにする。将来、言語を追加する場合に、既存コードの改修量が文言の追加だけに収まる状態を保つ。

## 2. 用語定義

| 用語     | 意味                                                                                                  |
| -------- | ----------------------------------------------------------------------------------------------------- |
| 表示言語 | アプリのUI文言・日時や数値の書式に使う言語。`ja`（日本語）または `en`（英語）。                       |
| 投稿言語 | Bluesky投稿に付与する言語タグ。表示言語とは別の概念である。                                           |
| 言語設定 | 利用者が明示的に選んだ表示言語、または「システム設定に従う」。                                        |
| 文言     | 利用者に表示する文字列。ボタン名・見出し・メッセージ・aria-label・placeholder・ページタイトルを含む。 |

## 3. スコープ

### 3.1 対象

- v2（`src/`配下）の全UI文言の日本語・英語対応。
- ヘルプ記事の日本語・英語対応。
- 日時・数値の書式の表示言語への追従。
- APIエラーに起因する利用者向けメッセージの日本語・英語対応。あわせて、特定のAPIだけがエラー文言を返している箇所を、他のAPIエラーと同じ仕組みに統一する。
- 表示言語の自動判定、設定画面からの切り替え、選択の永続化。
- ゲストモードのダミー投稿・ダミーEntryの日本語・英語対応。
- 文言のハードコード混入を検出する仕組み。

### 3.2 対象外

- `_legacy` 配下のフロントエンド・バックエンド。
- 日本語・英語以外の言語（ただし追加が容易な構造とする）。
- 言語ごとに異なるURL（`/en/` 等）の提供。
- Blueskyの投稿言語選択の仕様変更。投稿言語は表示言語と独立して従来どおり投稿ごとに選ぶ。
- 言語選択肢の名称の翻訳（各言語の自称表記を維持する）。
- OpenAPIスキーマのdescription等、開発者向け記述の翻訳。
- Bluesky・外部サービスから取得した投稿本文・プロフィール等ユーザー生成コンテンツの翻訳。

## 4. 機能要件

### 4.1 表示言語の決定

- FR-1: 言語設定が保存されている場合、その言語で表示する。
- FR-2: 言語設定が保存されていない場合、ブラウザの言語設定（優先順）から、対応言語のうち最初に一致したものを使う。いずれも一致しない場合は日本語とする。
- FR-3: 言語設定は「システム設定に従う」「日本語」「English」から選べる。「システム設定に従う」はFR-2の動作とする。
- FR-4: 言語設定はブラウザを閉じても保持される。保存先はブラウザ内に限り、サーバーには送信されない。

### 4.2 切り替え

- FR-5: 設定画面（ページ・ダイアログの双方）とログイン画面に、表示言語の選択UIを置く。ログイン画面は、ログイン前の利用者が言語を選べるようにするためである。
- FR-6: 選択すると、ページ再読み込みなしで、表示中の全文言（ナビゲーション、ページタイトル、フォーム、ダイアログ、ヘルプを含む）が即座に切り替わる。
- FR-7: 切り替え時、入力中のフォーム内容・開いているダイアログ・スクロール位置は失われない。
- FR-8: ページ遷移後も選択した表示言語が維持される。

### 4.3 文言

- FR-9: 利用者に見える文言は、日本語・英語のいずれにも未翻訳のまま残らない。
- FR-10: 件数等の数値を含む文言は、英語で単数・複数を正しく表示する。
- FR-11: 日時・数値は表示言語の慣習に従って表示する。
- FR-12: HTMLの言語属性（`lang`）は、表示言語と一致する。
- FR-13: 共有URLのメタ情報（OGP等）と初回HTMLの言語は、サーバーで描画されるページでは、リクエストのAccept-Languageに従う。保存済みの言語設定がこれと異なる場合は、初期描画後に言語設定の言語へ切り替わる。

### 4.4 APIエラー

- FR-14: APIはエラー文言を返さない。全てのAPIエラーは同一の仕組み（HTTPステータスと言語非依存の固定文字列）で返し、利用者向けの文言はHTTPステータスから表示言語で決まる。
- FR-15: ステータスに個別の文言が無いエラーや、通信自体の失敗は、汎用の失敗メッセージを表示言語で表示する。

### 4.5 保守性

- FR-16: 一方の言語にのみ存在する文言は、ビルド（型検査）で検出できる。
- FR-17: 文言を参照するコードに、存在しない文言キー・不足した置換パラメータがあれば型検査で検出できる。
- FR-18: コンポーネントに日本語・英語の文言リテラルが直書きされた場合は、テストで検出できる。例外として許可するもの（言語の自称表記等）は明示的な一覧で管理する。

## 5. 非機能要件

- NFR-1: 追加の実行時依存パッケージを導入しない。
- NFR-2: Cloudflare Workers上で、リクエスト間で言語状態が混ざらない。
- NFR-3: SSG対象ページのビルド出力は言語非依存に生成できる（利用者の言語設定に依存しない）。
- NFR-4: 初期表示のHTMLは日本語を既定とし、英語を選択している利用者は、初期描画後に切り替わることを許容する。ただし画面の再レイアウト（コンテンツの大きなずれ）を生じさせない。
- NFR-5: 既存の日本語表示は、文言・レイアウトともに変更しない。

## 6. 受け入れ条件

- AC-1: ブラウザ言語が英語で言語設定未保存のとき、`/settings/` を開くと英語で表示される（FR-2）。
- AC-2: ブラウザ言語が日本語で、設定画面で「English」を選ぶと、ページ再読み込みなしで全文言が英語に切り替わり、`<html lang>` が `en` になる（FR-5, FR-6, FR-12）。
- AC-3: 切り替え後に別ページへ遷移・再読み込みしても英語が維持される（FR-4, FR-8）。
- AC-4: 投稿フォームに入力途中の本文がある状態で言語を切り替えても、入力内容が保持される（FR-7）。
- AC-5: 英語表示で、スレッド返信数が1件のとき単数形、2件以上のとき複数形で表示される（FR-10）。
- AC-6: 英語表示で日時が英語の書式で表示される（FR-11）。
- AC-7: アカウント数上限に達したログインを試みると、英語表示では英語、日本語表示では日本語の「上限に達した」旨のエラーが表示され、APIのレスポンスに利用者向け文言は含まれない（FR-14）。
- AC-8: Accept-Language が英語のとき、サーバー描画ページ（Entry詳細）の `<html lang>` とOGPが英語になる（FR-13）。
- AC-9: 英語辞書から1キーを削除すると型検査が失敗する（FR-16）。コンポーネントに日本語の文言リテラルを書くと、テストが失敗する（FR-18）。
- AC-10: 既存の自動テスト（日本語表示を前提とするもの）が、日本語環境で全て通る（NFR-5）。
