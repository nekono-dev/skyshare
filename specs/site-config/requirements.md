# 運用者ごとの設定 要件定義書

## 1. 目的

Skyshare は OSS であり、別の運用者がフォークして同じコードを配備できるようにする。運用者ごとに変わる値（公開するドメイン・Cloudflare の配備先・運営者情報・アクセス解析）をコードに書かず、環境変数で受け取る。

## 2. スコープ

### 2.1 対象

- 運営者情報とアクセス解析の測定 ID の受け取り・検査・解決。
- サイトの URL と、Cloudflare の配備先（Worker 名・ドメイン・D1・R2）の受け取り。
- CI のワークフローへの値の受け渡し。

### 2.2 対象外

- lexicon の NSID の変更。運用者が違っても Entry を相互に読めるよう固定する。
- プライバシーポリシーの本文の書き換え。本文は実装に合わせて書き、値だけを差し込む。
- 旧 UI の設定。
- AI エージェント向けのブランチ運用の宣言。

## 3. 前提

- なし

## 4. 機能要件

- FR-1: 運営者の名称・窓口のメールアドレス・プライバシーポリシーの制定日と改定日は必須とし、本番ビルドで欠けているか形式が違うときはビルドを止め、欠けた変数名を示す。
- FR-2: 窓口の Bluesky ハンドルと Google アナリティクスの測定 ID は任意とし、未設定か形式が違うときは使わない。
- FR-3: 開発時（開発サーバーと単体テスト）は、必須の値が未設定でもダミー値で補って動く。
- FR-4: Google アナリティクスのタグは、測定 ID が設定されたときだけ出力する。
- FR-5: サイトの URL は公開するドメインの値から作り、開発時に未設定なら開発サーバーのアドレスを使う。
- FR-6: Cloudflare の配備設定は、Worker 名・ドメイン・ゾーン・D1・R2 をテンプレートの置き換えで作り、必須の値が欠けると異常終了する。
- FR-7: ステージングは、本番と別の Worker 名とドメインに、プレビュー用の D1・R2 を使い、ドメインが未設定のリポジトリでは行わない。
- FR-8: CI のワークフローとマイグレーションの補助は、運用者ごとの値を直接書かず、GitHub の Variables か生成した設定から読む。

## 5. 非機能要件

- NFR-1: アプリのコード・テンプレート・ワークフローに、運用者固有の値（ドメイン・D1 の ID・測定 ID・運営者情報）が0件である。

## 6. 受け入れ条件

- AC-1 (FR-1): 必須の値が欠けた環境では欠けた変数名を挙げた問題が返り、すべてそろえば問題が0件になる。
- AC-2 (FR-1): 形式の違う値は、それぞれ問題として挙がる。
- AC-3 (FR-2): 任意の値は省いても問題にならず、設定すればそのまま使われ、形式が違えば使われない。
- AC-4 (FR-3): 開発時は、必須の値がダミー値で補われ、任意の値は使われない。
- AC-5 (FR-4): 測定 ID があるときだけ GA のタグが出力され、ID が初期化に使われる。
- AC-6 (FR-5): ドメインを与えるとその URL になり、未設定なら開発サーバーのアドレスになる。
- AC-7 (FR-6): 与えた配備先の値が配備設定に入り、必須の値が欠けると異常終了する。
- AC-8 (FR-7): ステージングの配備設定は、別の Worker 名とドメインに、プレビュー用の D1・R2 を使う。
- AC-9 (FR-8): ワークフローとマイグレーションの補助に、運用者固有の値が見つからない。
- AC-10 (NFR-1): アプリのコードと配備のテンプレート・設定に、運用者固有の値が見つからない。
