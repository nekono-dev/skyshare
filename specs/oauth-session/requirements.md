# OAuth のログインとセッション 要件定義書

## 1. 目的

利用者がパスワードを入力せずに Bluesky の OAuth でログインでき、得たセッションで、API の利用・アカウントの切り替え・ログアウトを、アプリパスワードのセッションと同じように扱えるようにする。

## 2. スコープ

### 2.1 対象

- OAuth によるログインの開始と完了の API。
- v2 の API での OAuth のセッションの再開と、期限の前の更新。
- OAuth のセッションでの DPoP の証明を付けた PDS への要求。
- OAuth のアカウントへの切り替えと、ログアウトでの取消。

### 2.2 対象外

- ログインの画面と、認可の画面からの戻りの表示。
- アプリパスワードのセッションの扱い。
- Bluesky がホスティングしないアカウントの OAuth によるログイン。

## 3. 前提

- 前提: oauth-client — クライアントの識別・認可サーバーの探索・トークンと PDS への要求を使う
- 前提: account-session — セッションの cookie の形式とプールの規則を共有する

## 4. 機能要件

- FR-1: ログインの開始は、ユーザー名を受け取らずに Bluesky の認可サーバーへ、ログインの権限で認可の要求を事前に送り、認可の画面の住所を返す。
- FR-2: ログインの開始でハンドルの指定があれば、入力済みの指定として送る。
- FR-3: ログインの開始は、照合に使う途中の状態を、完了の API だけに送る10分の HttpOnly の cookie に入れる。
- FR-4: ログインの完了は、途中の状態との state と発行元の一致を確かめてから、認可コードをトークンに替える。
- FR-5: ログインの完了は、トークンの持ち主の PDS の認可サーバーが発行元と一致し、PDS がそのトークンで持ち主のセッションを返すことを確かめてから、セッションを作る。
- FR-6: ログインの完了で作ったセッションは、パスワードのログインと同じ規則でアクティブにし、プールが上限なら409で拒否する。
- FR-7: ログインの完了は、成否によらず途中の状態の cookie を消し、失敗には分類を返す。
- FR-8: v2 の API での再開は、アクセストークンの期限まで60秒を切ったときだけ更新し、更新したときだけセッションの cookie を書き戻す。
- FR-9: PDS への要求は DPoP の証明を付けて送り、最後に受け取った nonce を cookie で次のリクエストへ持ち越す。
- FR-10: OAuth のアカウントへの切り替えは、期限の近いアクセストークンを更新してからアクティブにし、更新できなければ401で拒否する。
- FR-11: OAuth のアカウントのログアウトは、更新用トークンを認可サーバーで取り消してから cookie から除き、取消の失敗では止めない。

## 5. 非機能要件

- NFR-1: ログインの開始と完了の応答の100%に、キャッシュを禁止する指定を付ける。
- NFR-2: トークン・認可コード・鍵を含む文字列を、応答の本文とログに出力する箇所を0件にする。
- NFR-3: 全リクエストで読み込まれる経路で、atproto のライブラリを静的に読み込む箇所を0件にする。

## 6. 受け入れ条件

- AC-1 (FR-1): 開始で、ユーザー名を含まずログインの権限を指定した事前の要求が送られ、認可の画面の住所が返る。
- AC-2 (FR-2): ハンドルを指定した開始では、そのハンドルが入力済みの指定として送られる。
- AC-3 (FR-3): 開始の応答に、完了の API のパスに限った HttpOnly で10分の途中の状態の cookie が付く。
- AC-4 (FR-4): 途中の状態と違う state・途中の状態が無い戻り・発行元の違う戻りでは、トークンを要求しない。
- AC-5 (FR-5): 持ち主の PDS の認可サーバーが発行元と違うトークンと、PDS がセッションを返さないトークンでは、セッションが作られない。
- AC-6 (FR-6): 照合と確認に成功すると OAuth のセッションがアクティブになり、別のアカウントがアクティブだったときはプールへ退避される。
- AC-7 (FR-6): プールが上限に達しているとき、別のアカウントでの完了が409で拒否される。
- AC-8 (FR-7): 拒否の戻りで、途中の状態の cookie が消え、拒否の分類が返る。
- AC-9 (FR-8): 期限まで余裕のあるセッションは更新も書き戻しもされず、期限の近いセッションは更新されて書き戻される。
- AC-10 (FR-8): 更新用トークンが失効しているとき、v2 の API が401で拒否される。
- AC-11 (FR-9): PDS への要求に DPoP の証明が付き、受け取った nonce が cookie に書かれて次のリクエストの証明に入る。
- AC-12 (FR-10): 期限の近い OAuth のアカウントへの切り替えで更新が行われ、失効していれば401になる。
- AC-13 (FR-11): OAuth のアカウントのログアウトで取消が依頼され、取消が失敗しても cookie から除かれる。
- AC-14 (NFR-1): 開始と完了の応答に、キャッシュを禁止する指定が付く。
- AC-15 (NFR-2): 完了に失敗しても、トークン・認可コード・鍵がログと応答の本文に現れない。
- AC-16 (NFR-3): 全リクエストで読み込まれる経路が、atproto のライブラリを静的に読み込まない。
