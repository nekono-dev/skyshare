# アンケートの運用

アンケートの聞き取り、翻訳、利用者の確認、登録、状態確認、期限切れ項目の除去を案内する。操作は `npm run survey` の専用 CLI だけで行い、`SURVEY_CONFIG` の値を直接変更しない。別の CLI や手動の JSON 削除手順を作らない。

## 新しいアンケートの聞き取り

アンケートの実施・追加を依頼されたら、依頼に既にある情報は聞き直さず、不足分をまとめて尋ねる。実施期間について尋ねるのは、終了日時（日本標準時、JST）だけで、開始日時は尋ねない。開始は初回登録時に自動設定され、既存アンケートの更新では元の開始日時が保持される。

必要な情報:

- 必須のタイトルと、任意の説明
- 質問ごとの文面、単一選択または複数選択の形式、選択肢
- 複数選択の選択数上限
- 「回答しない」の選択肢を含めるか
- 終了日時（JST）

入力文は日本語のみ受け付ける。自由記述の質問は扱わず、選択式の質問だけを作る。選択肢 ID は英小文字・数字・ハイフンを使い、質問内で重複させない。終了日時は JST として受け取り、CLI の下書きには同じ瞬間を表す ISO 8601 形式で記す。終了時刻そのものは開催期間に含まれない。

## 既存アンケートの更新

更新依頼では、最初に `npm run survey -- status` を実行する。結果にある ID と段階を示し、どの ID を更新するか確認する。対象 ID を特定してから不足項目を聞き取り、開始日時は尋ねず、既存の開始日時が更新後も保持されると説明する。下書きのトップレベルに対象の `id` を入れる。対象を特定できるまでは下書きを作らず、更新コマンドも実行しない。

## 翻訳と登録前の確認

1. `src/lib/i18n/locale.ts` の `LOCALES` を読み、日本語以外のすべての言語にタイトル・説明・質問・選択肢を翻訳する。対応言語を固定リストとして扱わない。
2. 日本語とすべての翻訳を、質問ごとに分けた一つの確認表にまとめる。表には必須タイトル、任意説明、質問、選択肢、単一／複数の形式、複数選択の上限、「回答しない」の有無を含める。
3. 表には開始日時が初回登録時に自動設定されること、更新では既存の開始日時が保持されること、依頼された終了日時（JST）を明記する。利用者が上限・辞退の有無も確認できる形にする。
4. 利用者に内容の明示的な確認を求める。確認前に `add` を呼ばず、下書きファイルも作らない。修正依頼があれば翻訳を含む表全体を更新して再提示し、改めて明示的な確認を待つ。
5. 明示的な確認を受けた後に限り、確認済みの内容で JSON 下書きを作る。形式は `tests/fixtures/survey-operation/drafts/without-id.json` を参照する。新規登録では `id` と `opensAt` を省略する。更新では対象 `id` を含め、`opensAt` は指定しない。質問・選択肢は各 `LOCALES` の文言を含める。
6. 下書きはリポジトリ外の一時 JSON ファイルに作成し、パスを安全に引用する。`npm run survey -- add --file <一時ファイル>` で登録または更新する。実行後は成功・失敗のどちらでも一時ファイルを削除する。
7. 確認だけを行う場合は `npm run survey -- add --file <一時ファイル> --dry-run` を使う。dry-run も明示確認後に作った一時ファイルに対して行い、処理後に削除する。CLI が出す要約の1行だけを報告する。

## 状態確認

状態確認依頼では `npm run survey -- status` を実行し、CLI の要約1行を報告する。結果には各アンケートの ID と段階（`upcoming`、`active`、`retained`、`expired`）、および `SURVEY_CONFIG` の使用量が示される。`status: no surveys` は設定されたアンケートがないことを示す。状態確認は設定と回答データを変更しない。

## 期限切れアンケートの除去

手動または main への取り込み前の除去では、まず dry-run の結果を確認する。

```sh
npm run survey -- prune --dry-run
```

除去対象を確認してから実際の除去を行う。

```sh
npm run survey -- prune
```

結果の意味:

- `removed <id>`: 除去したアンケート
- `kept <id>(rows)`: 回答または回答済み記録が残っているため保持したアンケート
- `kept <id>(unknown)`: 回答データを確認できず保持したアンケート
- `nothing to remove`: 除去候補がない

確認不能またはコマンド失敗の場合、設定は変更されない。`gh variable set` などで `SURVEY_CONFIG` を直接設定せず、JSON からアンケートを手動削除しない。手動削除すると、回答データの保持期限判定・削除の対象を特定できなくなる。

## コマンド出力と失敗時の扱い

成功・失敗を問わず、利用者には CLI が返す固定の1行だけを伝える。設定本文、回答、認証情報、外部コマンドの標準エラーを調べたり、貼り付けたりしない。`error: auth` はローカルの `gh` または `wrangler` の認証が必要、`error: invalid` は入力または既存設定の確認が必要という意味である。エラー時も一時ファイルを削除する。
